# MVP 验证方案

状态：早期候选方案，最新约束与范围以 `mvp-v0.1.md` 为准。用户已确认 Web app、手动带入信息、保留简单 AI；尚未开始实现。
用户偏好：少做假设，框架清晰后低成本验证。

## 已经清楚的产品方向

- 每日可完全编辑的建议页是主入口，包含行动安排和自由书写。
- 自然语言输入可以产生关联的 TODO、Event、Note 和链接资料。
- 跨日事项持续跟踪，在相关日期/临近日期回到主页。
- Review 帮助生成下一天的计划草稿。
- 一步暂放，不在每次移除时要求选择去向；可选建议与明确承诺需区别对待。
- 收藏资料希望被整理，并在有用时重新出现。
- Calendar 和 e-ink 是其他呈现方式。

## 实施前仅需解决的边界

1. 实际使用入口及数据编辑责任：独立 App 还是继续编辑 Notion。建议独立 Web，手工导入少量内容，先不做双向同步；用户尚未确认。
2. 试用设备和存储底线：常用手机/电脑，试验数据是否可交给所选模型处理，持久保存和导出的最低要求。实现前需具体明确，避免在当前阶段一次询问全部技术细节。
3. 自动操作范围：明确内容可入库并给回执；模糊日期保留未安排；计划是建议，已选内容不被 AI 静默覆盖。建议用该保守默认进行验证，具体规则需确认。

## 验证假设

- A：每日草稿确实减少回忆和安排成本，且用户愿意继续自由书写。
- B：事项能可靠跨日返回，完成、改期和暂放后结果符合预期。
- C：从收藏中找回的资料能帮助实际行动，价值不只在于自动摘要。

## 三种验证方式

| 方式 | 能验证 | 相对投入及局限 |
| --- | --- | --- |
| 可点击原型/人工代操作 | 页面组织、操作含义、用户偏好 | 最低投入；不能验证持续状态和真实跨日使用 |
| 薄而完整的可用版本（建议） | 输入、编辑、跨日、review 及少量资料重访 | 小到中等投入；限制集成和资料类型 |
| 连接现有多服务的版本 | 自动导入、通知和设备输出的完整习惯 | 投入高；集成故障可能掩盖核心产品价值 |

## 候选第一版范围

### 每日页面与事项

- 单用户，每日建议页可编辑，有自由文字和关联任务/事件。
- 自然语言输入，简短识别回执，可修改和撤销。
- 优先识别明确日期，显示绝对日期，模糊内容保持未安排。
- 完成、改期、一步暂放；保留原始记录及事项身份。
- 一次生成今日草稿；后续变化不覆盖手动编辑。
- 页面交互可以采用简单编辑器与可编辑事项块；任意删除或重写整段文字后都能无误推断结构变化，不作为首轮可靠性承诺。此处是对“完全可编辑”实现方式的候选取舍，需让用户知道。

### Review 与跨日

- 一个短 review 入口，回顾完成/未完成、必要调整、生成次日草稿。
- 首轮打开页面时按日期产生应出现事项；草稿可手动触发生成，以便先验证内容是否有用。
- 无人打开时的主动通知与自动后台生成未被此方式验证，若主动提醒是必要行为，应增加一条可工作的提醒渠道。
- 固定日程/截止事项继续跟踪；暂放的可选建议不机械地次日重推。
- 暂放后明确说明今天不再推荐；首轮降低频率可用简单可解释规则，不引入复杂学习机制。

### 收藏资料的最小实验

- 少量真实收藏，首轮仅支持可读取的文本网页，不能读取时允许粘贴正文并明确状态。
- 保留来源、摘要及少量主题关联，在一项真实任务中尝试找回相关资料。
- 不把未获取正文的链接标成已整理，不自动声称覆盖视频或完整 GitHub 仓库。
- 这是知识价值的初步验证，尚不等同于完整 LLM Wiki；跨来源主题页与持续更新效果在后续小轮实验验证。

### 验证期基本保障

- 持久保存、历史页可访问、文本可导出，不丢用户试验期间写下的内容。
- 操作失败可见，不虚构成功；明确日期和截止状态优先保证可靠。

## 暂缓

- Notion/日历等服务双向同步及批量历史迁移。
- 完整 Calendar 月/周交互，可先用按日期列表检查未来事项。
- TRMNL 专用接入，可先预览 Top 3 等将来要输出的内容。
- 视频转录、复杂仓库分析、自动长期个人画像。
- 复杂习惯学习、智能降频算法、无限自定义组件。

## 一轮真实验证

候选试用时长：5–7 天，按用户实际节奏调整。

使用真实资料，至少覆盖：一个跨日未完成事项、一个未来日期事项、一个改期、一个暂放、一次跳过 review 后恢复、一个收藏资料被实际调用的场景。

观察而非预设强指标：

- 早上从打开页面到接受/调整计划，需要多少时间与纠正。
- 是否仍需回 Notion 或翻旧页补找事项，以及原因。
- 事项有没有漏回、误回、重复、错误改期；错误日期/漏期限需修复后再继续扩大范围。
- 暂放是否减少打扰，是否又让用户失去对承诺的信任。
- 是否有一份资料帮助完成或改变了一项实际行动；没有可用机会时延长该实验，不用纯点击量替代价值。
- 试用结束后愿不愿意继续使用，具体因为什么。

## 决策原则

先验证每日闭环，必要时把知识重访作为并行小实验。根据真实摩擦只增加一项最有帮助的能力；若核心闭环无价值，先改流程，不以增加 Calendar 或更多输出掩盖问题。
