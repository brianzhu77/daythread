# 每日页 App：MVP v0.1

状态：产品范围收敛稿。用户已确认以下约束；具体范围取舍为助手建议，尚未实现或完成实际验证。

正式规格已拆分并移至 [Daythread specs](/Users/dogrod/Developer/daythread/README.md)。本文件保留为此前范围讨论记录；后续实施以正式规格及明确修订为准。

## 用户已确认

- 独立 Web app，无需 Notion 数据迁移或同步，接受手动带入信息。
- 保留自然语言入口，把输入与已有信息直接交给 AI。
- 首版不优化提示词、检索或上下文，先测功能和日常循环是否流畅。
- 每日建议页包含行动安排，页面可编辑。
- 移出今天不应每次询问去向，也不应形成要求逐条维护的无限积压清单。
- 用户补充：需要类似 Pages/Blocks 的内容存放能力，接受手动收集，再从 daily note 引用。自动抓取可暂缓，基本保存与引用需要进入首版。

## 验证目标

行动循环：录入 → 理解和保存 → 今日页 → 处理事项 → review → 次日接续。

资料循环：手动收集 → 保存为独立 Page/Blocks → 查找 → 在 daily note 或事项中引用 → 写下使用结论。

用户应能用它完成几天真实规划和记录，观察是否减少回忆、重复录入及跨日整理。

## 建议的最小界面

### 今日页（主入口）

- 日期导航与自然语言输入。
- 系统起草的今日安排、建议行动、自由正文。
- 简短识别回执：创建/更新了什么，日期具体是什么；允许纠正与撤销。
- 任务与事件以可编辑关联行存在，正文自由修改，顺序可调整。
- 完成、改期和一步暂放；明确取消作为独立操作。
- 用户编辑后，AI 不自动重写整页；主动触发重新整理时展示待应用变化。

### 简单未来事项列表

- 按日期检查未来任务和事件，以及临近截止事项。
- 不做完整月历或拖拽排期。
- 暂存与历史内容可查找，不要求用户每天清空。

### Pages / 资料库（补入首版）

- 新建、打开、编辑和查找独立页面；手动粘贴文章、项目介绍、摘录与来源链接，刷新后仍保存。
- Daily note 是带日期的 Page，普通 Page 可保存资料、项目和主题笔记；这是建议的统一组织方式。
- 基本 Block 建议支持段落、标题、列表、待办、引用文字；事件可作为带日期时间的关联块呈现。
- 每个 Page 和 Block 有持续身份，用于引用及任务跨日跟踪。
- 支持引用整页或某一段 Block，点击可以定位原内容；页面内展示少量预览。
- 引用同一任务时显示同一完成状态；移除引用不删除原资料，不创建重复任务。
- 首版用搜索/列表选取引用，提供简单反向引用列表，以便从资料回到使用它的日记。
- 不以多层嵌套、通用数据库、复杂排版或完整 Notion 编辑器作为首版前提。
- 上述具体块类型及引用交互为建议，Pages/Blocks 存放并引用资料的需求已由用户明确提出。

### 简短 review（可在今日页内展开）

- 查看今日完成与未完成事项。
- 用户可直接写一句调整意见，例如“材料等回复，明天先做另一件”。
- 根据最新状态生成明日计划草稿；打开明日页时纳入当前实际安排。
- 不强制逐条选择，跳过 review 后也能继续使用。

## AI 的最小职责

- 用少量固定指令和当前试用数据直接理解自然语言，提取/更新任务、事件、笔记与日期。
- 对象或日期有歧义时保留原文并显示疑问，不编造关键时间或把不确定更新直接应用到已有承诺。
- 起草每日页、总结 review。
- 模型提出记录变更，App 保存并管理日期、状态与事项身份，不依靠模型每次重新猜测历史状态。
- 正常录入可直接记录并给回执，避免每条确认；歧义修改才需要澄清。
- 不做长期个人画像、智能推荐排序、复杂降频学习、向量检索或多 agent。
- 模型服务与凭证配置属于后续实现条件，尚未选择。

## 暂放的简单规则（候选默认）

- 一个动作移出今天，给出可撤销反馈，不弹去向选择。
- 不自动把暂放事项顺延到次日。
- 对明确承诺保留未完成状态及既有截止/提醒；对未接受建议可停止主动推荐。
- 首轮通过明确日期、用户主动安排或 review 请求使它再次出现，不做 AI 自主挑选重现时间。
- 这会验证暂放与找回是否顺手，尚不验证智能情境推荐。

## 资料处理的首版取舍建议（已修正）

- 保存链接、用户粘贴的内容和备注到独立资料页，允许在 daily note 和任务处引用整页或具体段落。
- AI 可直接基于已提供的正文生成简单摘要或回答。
- 先不做自动抓取、视频转录、仓库分析和跨来源 wiki 自动维护。
- 首版必须验证“存进去、找得到、引用回来”的基础资料循环；自动维护完整 wiki 仍可暂缓。此前把知识复用整体移到下一轮过度收缩范围，已修正。

## 暂缓的输出与集成

- 完整 Calendar、TRMNL、Notion 与外部日历集成。
- 无人打开时的后台自动生成与多渠道通知。
- 第一轮在打开今日页或主动操作时生成草稿；每日 review 主动提醒仍是原始需求，但这一取舍尚未验证提醒效果。若试用表明忘记 review 是主要阻碍，优先增加一个定时提醒渠道。

## 首轮验收场景

1. 输入明确日期事项，保存后刷新仍存在，未来事项列表日期正确。
2. 今日写下未来安排，到对应日期能够出现；历史输入保留。
3. 一段输入可形成相互关联的资料与任务；未提供正文不伪装抓取成功。
4. 完成/改期后各处状态一致，不产生重复事项。
5. 暂放不要求选择去向，次日不会原样自动重推，可撤销或主动找回；既有期限不会被取消。
6. 修改正文和调整今日安排后，AI 后续操作不静默覆盖。
7. Review 后有明日草稿；跳过一天仍能继续使用，不遗失承诺。
8. 模型失败时原始输入保留，失败可见且可重试。
9. 试用文字和事项持久保存，可导出；自然语言日期以用户本地日期为基准。
10. 手动保存一份资料为普通 Page，在 daily note 引用该页及其中一个 Block，可定位回原内容。
11. 删除 daily note 中的资料引用后，原资料仍保留；多个位置引用同一任务时状态一致。
12. 能在资料页查看引用它的 daily note，并写下使用结论；资料的原始内容与 AI 摘要可区分。

## 验证方式

连续使用约 5–7 天真实内容，记录：是否仍频繁回旧工具找事项、哪些识别需要纠正、是否出现遗漏/重复、每日页被如何修改，以及暂放与 review 是否带来额外负担。根据主要摩擦决定下一项能力，不用增加外围功能替代修正核心循环。

## 后续顺序

每日行动循环和手动资料保存/引用循环能用 → 补足实际阻碍（如 review 提醒）→ 自动摄入与 wiki 维护 → Calendar/e-ink 等其他出口。
