## 用户已明确的意图

- 自己做一个 App，实现类似 Karpathy LLM Wiki 的知识整理能力。
- 加入更贴合自己的功能，包括个人 daily note。
- 输出侧提供实时 dashboard，呈现个人定制事项、待办和提醒。

## 初步讨论框架（助手提出，待用户确认）

1. 输入：日常随手记录、daily note、外部资料。
2. 知识：原始资料、AI 整理的知识页、关联与来源。
3. 行动：事项、待办、提醒及其状态。
4. 呈现：dashboard、检索问答、日/周回顾。
5. 个性化规则：关注领域、页面布局、AI 如何整理、何时提醒。

候选循环：记录或导入 → AI 整理知识并提出行动建议 → 用户处理事项 → 结果回到记录与知识库。

## 已明确的三个痛点与目标

### 1. 每日规划与 review

- 当前每天在 Notion 写 daily note。
- 每天有未完成事项，可能需要流入第二天。
- 希望系统提醒每日 review，通过有引导的 routine 提升 review 质量。
- 希望第二天自动先生成一版当日计划，减少规划与回忆的消耗。
- 尚未确定所有未完成事项是否自动进入次日计划、计划生成时间，以及哪些步骤需要用户确认。

### 2. 收藏内容的再利用

- 经常收藏文章、视频和 GitHub 项目到 Notion，之后基本不再访问。
- 相信这些内容有价值，希望系统提升零碎内容的价值。
- 希望借鉴 LLM Wiki，但具体的整理、重访和应用方式尚未确定。

### 3. Dashboard 与 e-ink 输出

- 已有使用 TRMNL 系统的 e-ink 屏幕。
- 希望展示当前重要的事项，例如今日 Top 3、TODO，以及对当下有帮助的 quotes/notes。
- TRMNL 是预期输出渠道，用户明确表示具体系统本身不重要。
- 刷新频率、展示容量、内容挑选规则和设备交互方式尚未确定。

### 4. 用 daily note 串起未来事项

- 用户会在当前 daily note 中记录未来事项。
- 希望事项在对应日期或临近日期的 daily note 中体现出来。
- 希望可能增加 Calendar view，属于候选需求，尚未确认第一版范围。
- 用户的概括："其实有点像用 daily note 串起来所有的事"。
- 需要区分事项的记录日期、计划处理日期、截止日期/发生日期，以及希望提前出现的时间。
- 是否支持自然语言日期解析、模糊时间、重复事项及外部日历同步尚未确定。

## 对产品主线的最新理解（待验证）

### 用户提出的初步产品形态

- Home page 是每天的主入口，以自然语言输入。
- 候选类目：TODO、Events、Notes（包括灵感）。
- 系统从输入中提取信息、归类并入库。
- 输入链接时抓取对应内容，最后进入 wiki。
- 输入带日期的事项时，识别并记录，在对应日期或临近日期逐步回到 Home。
- 用户当前要求：先做产品层面的压力测试，推演整个 App 的运转。

### 最新交互方向：可完全修改的每日建议页

- 用户提出：提供一版 suggested 的今日自由书写页，包含今天的行动安排，页面内容可以完全修改。
- 这回应了此前“行动安排与自由书写谁优先”的探索：用户倾向将两者结合为一份可编辑的每日页面。
- 尚待澄清：页面中的任务修改如何影响持续事项、删除与取消的差异、AI 后续更新如何与用户编辑共存。
- 助手建议：生成初稿后由用户主导；任务/事件在文档中保持关联；后续新信息以可合并建议出现，不静默覆盖用户编辑；删除页面中的事项默认移出当天，取消需明确动作。以上均未确认。

### 用户新增约束：避免积压与逐条选择

- 担心大量“移出今天”让总待办清单不断增长，最终不可维护。
- 不希望每次移除时选择去向或处理方式，认为这会带来过多操作负担。
- 希望参考现有优秀交互，探索其他 UX。
- 当前探索：统一的一步暂放、撤销反馈、降低再次推荐频率、按当前项目/情境找回、低频批量整理。
- 重要边界（助手建议）：未接受的建议/想法可降低展示频率；明确承诺、截止事项及提醒不因多次跳过而自动取消或静默失去提醒。没有截止日期也可能是明确承诺。
- 持久保存的条目数量可以增加，但不应要求用户逐条维护全部库存；真实承诺超出容量时仍需显式调整范围或时间。

### 交互参考（官方文档，供设计借鉴）

- Things：Today/Upcoming/Anytime/Someday 区分关注时机；开始时间与截止日期分开。https://culturedcode.com/things/support/articles/2803579/
- Sunsama：未完成任务跨日流转，多次连续流转可自动归档，归档有提示且可配置。https://help.sunsama.com/docs/getting-started/basics/task-rollover-and-recurring-tasks-the-basics/
- Readwise：Daily Review 允许调节来源频率，展示过的 highlight 再次出现的概率下降。适合借鉴资料重访，不直接套用到个人承诺。https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights

Daily note 是贯穿记录、安排、回顾和行动的每日入口。跨日事项应保留一个可跟踪的身份，在每日页面和 Calendar/Dashboard 中按日期与状态呈现。知识资料可关联这些事项并在需要时出现。

示例（助手举例，并非用户的真实事项）：今天记录“下周五提交材料，提前三天开始准备”。系统保留今天的原始记录，在准备日呈现准备事项，在截止日呈现提交事项；完成或改期后，各视图同步反映。

建议让日期视图引用同一事项，保留每天的完成/改期记录，避免简单复制导致重复或历史被覆盖。具体数据结构未定。

## 基于场景的设计建议（未确认）

- 把日常闭环作为讨论主线：每日记录 → 引导 review → 次日计划草稿 → 当日行动与展示 → 再次 review。
- 未完成事项保留独立身份；跨日改变计划日期或安排，避免每天复制出新的任务副本。
- review 帮助区分继续、延期、等待、放弃，以及阻碍原因；避免未完成事项无限累积。
- 收藏内容保留来源，并把摘要、观点、适用情境与当前任务/项目关联；通过使用情境重新出现。
- Dashboard 展示精选结果；Top 3、待办和引用的来源及选择逻辑应能在 App 内查看或调整。
- 优先详细探索 daily note/review/次日计划，因为这一流程能为知识推荐和 dashboard 提供上下文。
- Notion 是否继续作为主编辑入口尚未决定。
