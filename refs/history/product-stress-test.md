# 个人 App 产品压力测试

状态：讨论稿，规则与范围均为建议，尚未确认。
依据：用户提出 Home 自然语言入口、TODO/Events/Notes、链接进入 wiki、未来事项按日期返回 Home。

## 主要判断

产品成立的关键，是让用户可核查系统理解了什么、未来会怎样处理，并能在没有每日整理习惯时仍然可靠运行。自动归类只是其中一步。

Daily note 保存当天的输入和发生过的变化；事项持续存在，Home、Calendar、Dashboard 按需呈现同一事项。系统可以重算建议，但不应重写用户原文或悄悄改变承诺。

## 日常运转建议

1. 早上呈现既有安排、需要关注的期限和建议的今日计划。明确区分固定事项与 AI 建议。
2. 白天统一输入，先保存原文，再提取多个相关对象。呈现简短识别回执，允许直接修改、撤销或用自然语言纠正。
3. 链接异步处理，状态明确为已保存、处理中、已整理或失败/部分可用；原始链接始终保留。
4. 日期规则触发事项返回；AI 解释原因、建议准备动作和关联资料。日期变更更新未来安排，并保留历史。
5. 晚间通过简短 review 处理完成、继续、延期、等待和取消，生成次日计划草稿。跳过 review 不得使事项丢失。

## 压力场景与建议行为

| 输入/情境 | 容易出的问题 | 建议行为 |
| --- | --- | --- |
| 链接加一句“下周三开会前试一下” | 只存链接或只存待办 | 同时创建资料与待办并关联；会议若无已知来源，不自行捏造 |
| “今天想到，也许以后可以学画画” | 感想被升级成承诺 | 存 Notes/想法，不自行安排日程 |
| “下周五之前交，周三开始准备” | 截止日与执行日混淆 | 明确分别保存；相对日期用输入时的本地日期解析并显示绝对日期 |
| “过阵子研究这个项目” | AI 自作主张给日期 | 保存为未安排/以后考虑，可在 review 中重访 |
| “明天下午去一趟” | 缺对象、缺必要信息 | 保留输入并提出一个有针对性的问题；不声称已设置精确提醒 |
| “会议改到周四，准备工作也顺延” | 创建重复会议或关联错对象 | 有唯一明确对象时更新，多个候选时先消歧，展示变更摘要 |
| “太累了，不想做了” | 擅自取消全部待办 | 作为记录；取消需要明确对象和意图 |
| 收藏文章里出现“明天完成清单” | 资料正文被当成用户指令 | 来源内容进入知识整理，不直接变成个人承诺 |
| 链接无法获取完整内容 | 生成假摘要并声称整理成功 | 显示实际获取范围，可重试或补充正文，不虚构内容 |
| 连续十天没有 review | 主页堆满逾期事项或事项消失 | 提供恢复流程，先展示重要期限与当前安排，其余汇总待整理 |
| 收藏了大量内容 | 每天收到大量无关推荐 | 优先匹配当前事项；少量可控展示，支持少推/不再推，无合适内容可留空 |
| 日历日期已经过去 | 把未完成事件当作待办无限滚动 | 事件保留历史；需要的跟进另行产生或由用户明确确认 |
| 当天中途修改/完成事项 | Top 3 或 e-ink 显示旧状态 | 各视图引用同一状态；外部显示带最近更新时间，更新失败可见 |

## Home 的容量与分区

- 今天：既有安排、已选定的今日行动与 Top 3。
- 需要注意：临近期限、应跟进事项。说明出现原因。
- 输入与今日记录：随手输入及当天记录，避免被推荐内容挤占。
- 少量相关资料：优先关联当前事项，有用才出现。
- 未安排/待澄清/积压内容有可访问的去处，不全部挤在首页；关键期限不得因容量限制被静默隐藏。

“逐步返回”的一个示例：准备窗口先进入近期关注，计划执行日进入今日计划，临近截止时变为更显著提示。具体时间由用户或可解释规则决定，不统一规定所有事项都提前三天。首页提示与主动通知分别配置。

## 自动化方式的选择

1. 每条都确认：可控，但日常输入成本高。
2. 全自动归类和安排：流畅，但误判容易改变用户承诺。
3. 建议采用渐进确认：明确内容直接记录并给回执；模糊内容保留为未安排；涉及歧义对象、日期或改动时集中澄清；AI 优先级和时间安排保持为建议。

## 可靠性的底线

- 原始输入可追溯，可修改、撤销；日期解析展示绝对日期。
- 事项完成/改期同步影响 Home、Calendar、Dashboard 与未来提示。
- 过期不等于自动完成，取消与延期含义不同。
- 日期、状态、提醒由稳定记录和明确规则管理；AI 负责理解、总结、建议与关联。
- 个人感受、收藏观点、AI 推断与用户明确确认的事实/承诺保留区别，不把暂时情绪固化为长期个人结论。
- 用户几天不使用仍保留全部事项，回来时可以恢复，不必补写每一天。

## 候选第一版闭环（未确认）

自然语言输入 → TODO/Events/Notes 与链接资料 → 明确日期安排 → 今日 Home 与简单 Calendar → 完成/延期/取消 → 引导 review → 次日计划草稿 → 少量 wiki 关联资料重访。

e-ink 可先展示相同 Home 的精选内容。复杂个人画像、多服务双向同步、无限自定义视图、自动拆分大型项目可后续再评估。

## 验证方式

拿真实三天的 daily note 和若干收藏链接，逐条模拟输入，检查：识别回执是否可信、模糊事项是否正确保留、未来返回时机是否合适、改期是否连贯、漏 review 后是否能恢复，以及回流资料是否真的被使用。观察需要多少次纠正，而不只看归类结果。
