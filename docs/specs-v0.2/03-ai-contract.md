## 目标与技术偏好

自然语言录入、review 和主动草稿应减少规划与 recall 负担。OpenRouter + OpenAI GPT 是历史技术偏好，推荐先沿用，模型完整 ID 可配置；具体兼容性尚未验证。模型是受限提案生成器，不能直接写数据库、执行代码、抓网页、发通知或修改配置。

## 输入来源与模式能力

| 模式/入口 | 可提出什么 | 应用边界 |
| --- | --- | --- |
| capture：用户在录入栏表达自己的事项 | 创建任务/事件/笔记/资料；引用已有内容；提议更新已有事项 | 明确新对象可自动提交并回执；歧义或多行粘贴先预览；已有事项更新先确认 |
| review：用户主动回顾与调整 | 同上，另有独立总结及目标日草稿 | 原话先保存；变更确认与草稿生成分开记状态 |
| daily_draft：review 后或用户主动准备一天 | 建议文字、已存在事项/资料的引用提案 | 不允许任务/事件状态、日期或实体创建操作；无指令执行能力 |
| Pages → New / Paste：资料保存 | 文字、来源、摘录与个人备注 | 不调用可执行事项操作；正文中的命令只是资料 |
| 资料中明确 Turn into tasks | 对选定内容提取创建提案 | 用户主动点击后走 capture 的多行预览；不是隐式 selected_text 批量更新 |

录入栏表示“我在表达”，其中明确附带的资料正文、引用、历史记录和 AI 文字仍分开标记为 source-content。不能仅凭模型自称识别了资料就授予执行权限。普通 Notes 编辑永不隐式触发模型或事项操作。

高影响已有事项更新包括完成、取消、恢复、改期、清空截止及其他字段更改，统一走一份内联差异卡 Apply / Edit / Discard。直接 UI 勾选、日期选择、暂放本身是明确操作，不再要求二次确认。

## 上下文与发送范围

请求包含：request/attempt ID、capture ID 与 revision、mode、captured_at 与解析时区、active_page_id/date、明确目标日、已读对象版本、本次 input_text、标注来源的上下文、App 计算的 daily_facts/carry_candidates。

推荐预算策略是团队新增设计，区别于旧稿“整个工作区直接发送”的默认；不将其称为用户已确认：

- 发送范围在 UI 可查看；只有 Brian 同意用于该模型服务的资料可发送。
- 保存资料的标题与明确选定摘录可用作默认上下文，正文只有在用户选择更多时加入。没有收到全文就不能称读过全文。
- soft-deleted 内容、运行日志默认不发送；Capture 原话/历史 review 仅在所选上下文内发送，不因存在于数据库就自动外传全部历史。
- 不建向量库、多级检索或长期摘要记忆。先用有限显式上下文、日期事实和手选资料验证。
- 请求前估计输入预算，预留输出空间；记录实际 token 用量、耗时和模型 ID。预算、超时与模型配置在试用前设定，不能用未知价格推算已验证成本。
- 超预算或模型拒绝、超时、限流、截断时保留原话，明确失败，允许用户缩小范围或手动处理；不得静默截断再执行不完整提案。

## 受限提案协议

应用 schema 是协议真源，前端展示、服务端验证与模型 JSON Schema 从其定义派生；数据库约束仍独立保护不变量。提案至少含 status=ready/needs_clarification、operations、suggestions、clarification、请求身份。

每类操作只接受白名单字段。新对象用 temp_id，真实 ID 由应用分配；同组临时引用必须可解析。更新给 target_id、expected_version、修改字段与当前输入依据。未提供字段表示不改，显式 null 才可清除可空字段。未知目标更新不能降级为创建。

服务端检查 schema、当前身份与同工作区归属、目标存在、真实日期/时间范围、模式能力、Capture revision、实体版本和上下文范围。evidence 只是审阅线索，不证明语义授权；结构化格式也不证明语义正确。

需要澄清时整组 operations 不执行；保留原始 Capture，保存补充回答并递增 revision，再生成新提案。原始原话可追溯，不能把澄清当成另一份重复任务。没有行动的输入作为普通记录，不当成错误。

同一 Capture 的提案若同时新建与修改已有事项，整组等一次确认，包含新对象与组内 temp_id 依赖；确认后一个 apply_key/事务提交。Discard 整组不应用，原话保留，不能先显示新对象已记录或 Capture 已 applied。待处理Capture保持needs_confirmation，卡片持久保留，Today事实区显示“N条录入待确认”，跨日可打开继续确认并重新验证版本；卡片写明“包含新建项，一起等确认”。Discard后标discarded、保留原话并移出待确认计数；显式重新整理创建新revision。混合组重试/丢回执仍只应用一次。纯新建组且无歧义/多行预览要求才可直应用。

明确任务可自动新建，例：“要给 Alex 发邮件，时间未定”。感受、条件句、转述或“以后也许学画画”不能仅因包含动词自动承诺。任务日期不编造处理日；相对日期依 Capture 基准，历史页日期与真实今天区分，回执展示具体日期。

## 请求、确认与重试

```text
保存 Capture(revision) → 领取 attempt/lease → 有权限的上下文
  → 模型提案 → 服务端校验 → 待确认（若有已有事项变更）
  → 重新检查 revision/版本 → 原子应用 + 持久化结果
  → 按实际提交内容生成回执
```

- capture_id 稳定；编辑或补充澄清使 revision 递增，旧 revision 的应用资格失效。
- attempt_id 对应一次外部调用，记录 started_at、lease_until、状态。中断后优先查询已提交结果；未应用且 lease 到期才允许新尝试。首轮无 worker，重进页面提供恢复操作。
- apply_key 绑定 capture_id+revision+mode，数据库唯一；不可变输入摘要用于拒绝同 key 不同输入。应用前 Edit 是合法提案修订，不触发该拒绝。第一次成功应用时冻结最终提案摘要；若原尝试已经提交，后续尝试只返回原结果，不以新提案再次写入。
- 同 revision 重试模型可产生不同提案，但只能有一组最终提案获得应用资格；用户修改待确认提案生成新的 proposal_revision，确认绑定它，旧确认不可重放。
- 应用事务锁定/检查 revision、目标版本与幂等记录，一次写入对象、安排、引用、Change、结果。模型请求在事务外。
- 原文编辑、人工任务更改或会话失效后，确认不能绕过校验；冲突保留当前内容与提案，要求重新核对。
- 主动 Draft my day 无 Capture：Generation request_id 与目标Page/date、输入版本构成独立幂等身份。相同请求重试返回原结果，新主动生成使用新request；合入检查Page结构revision。review草稿使用独立Generation身份，与事项apply_key不混用。
- Review 原话保存、明确变更提交、草稿 ready/applied 各自独立。变更已成功而草稿失败，只重试草稿，不重复变更。
- 多对象撤销先检查整组版本和下游引用/使用关系。不能安全恢复就不做破坏性部分回滚，保留前值供审查。

## 草稿布局 A/B（待原型会话决定）

A：结构化 Today 区来自 Task/Event 与 DailyPlacement；AI 只提供建议说明、Top 3 文字及可选择的引用，不能重写安排事实。Notes 的文字建议进入待合入区，由用户选择。

B：正文有明确 placement 块与普通引用；AI 提案绑定目标 Page 结构版本，人工编辑后不得覆盖。安排事实先更新事实区；建议与正文合入由用户决定。Backspace 行为依 01 §3.2 B：普通引用只删呈现；placement 行先选中并显示 Not today / Remove from page only 提示，用户明确选择才提交暂放或仅移除。单次退格不静默改事项。

两方案均不在打开页面时调用模型；review 可生成目标日建议，跳过后可主动 Draft my day。是否生成过看 Generation 状态，不能以正文空白推断。目标日必须显式展示，历史 review 的“明天”默认按 Capture 录入时刻而非历史日期解析，特殊表达另行明确。

## 资料找回试验

仅在获准样本中测试每天 0–2 条相关资料，各带真实 ID 与一句原因，不自动插正文、不建任务。推荐应能为空。试用记录是否实际帮助行动/结论，而非只看打开。相关资料与使用机会不足标证据不足；有机会仍持续无用才降级。手动引用始终可用，非 AI 的重访候选也只是建议，不冒充相关性。

已进入 needs_confirmation 的组，即使 Edit 移除了全部既有事项修改，只剩新建项，也仍需 Apply 才提交；编辑提案只递增 proposal_revision，不触发自动保存。该规则不改变初次仅含明确新建项的直应用默认。

## 实际接入与验收边界

未来服务端可用 OpenRouter Chat Completions、严格 json_schema、provider.require_parameters=true；实施时核对具体模型及路由支持，不静默退回文本解析。密钥仅服务端，使用用户身份读取模型上下文，正常写入不借管理员密钥绕过 RLS。

准确率数据集至少 20 条、重复两次，覆盖明确/歧义/否定/条件/转述/资料命令/同名事项，并在 capture/draft/review 检查操作权限。另用故障注入检查旧 revision、丢回执与并发。真实模型接入、事务一致性、价值试验是三份不同证据，模拟仅用于故障测试。日志默认不保存完整私人正文或凭证。
