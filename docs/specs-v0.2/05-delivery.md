## 布局 A/B 与编辑器实验（待原型会话决定）

A：结构化 Today 区由事项事实、当日选择/排序驱动，Notes 是自由正文及普通引用。优点是无需把计划合入文档；代价是计划不能与随笔交错。实验只覆盖 Notes 的基础文字、引用、稳定 ID 和保存，不预建自有 task 编辑器平台。

B：计划在正文，placement 块与普通引用明确区分；Task 是事实，DailyPlacement 是当日选择，Block 只是呈现。需要验证同日重复引用、删除与显式暂放、排序、合入与结构版本冲突。不能暗中让编辑器快照成为第二套事项状态。

实验应检查中文输入法、拆合段、移动、复制粘贴、删除/恢复、刷新往返和跨页完成后编辑器撤销。新复制块有新 Block ID，目标事项 ID 保持；拆合时原目标保留或显示移除，不错误指向别段。

比较逐块行持久化与每页规范 JSON+引用索引，两者都只保留一个正文真源。默认先试逐块行；若适配/撤销代价过高可选页面 JSON，明确搜索/反链索引的事务成本。页面级引用不是悄悄删除段落定位需求，块级引用仍在建议范围，任何裁撤由 Lead 集中上呈。

## 数据写入与运行边界

```text
用户操作 → 会话与所有权验证 → Capture 先保存（若模型操作）
 → 事务外模型调用 → 校验/确认 → RPC 事务
 → revision/实体版本/apply_key 检查 → 关联写入与 Change/结果
 → 返回实际回执 → 缓存刷新
```

外部模型调用不占数据库事务。中断后先读已应用结果；未完成 attempt 超过 lease 才重试。允许重复调用费用的风险应记录，不允许重复应用。Review 草稿失败只重试生成。

应用最初可本机运行连接获准 Supabase，是否远程部署及常用设备待明确。联网依赖、保存失败后当前会话保留输入、会话过期与重登录需有可见状态；没有实现本地持久队列时不声称离线可用或刷新后恢复未保存文字。

未来配置示例仅含占位值：OPENROUTER_API_KEY（服务端）、OPENROUTER_MODEL（核对的完整 ID）、Supabase URL 与 publishable key（可公开项目配置）、工作区时区。权限靠 Auth/RLS，不靠隐藏 URL。正常应用不要求管理员密钥；迁移使用独立授权流程。不要把凭证写到文档、导出或日志。
