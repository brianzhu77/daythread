# Place: provider and external-service review

Ratchet · 2026-11-13 · task 352. Reviewed `place.md` at main 968d1508 and Lead ad34ae2c. This is a design review before D15, not verification of an implementation. No private queries, location or workspace data were sent to providers.

## Conclusion

The chosen providers support the proposed interactive use. Proceed with the signed-in Worker boundary and the acceptance checks below. Neither provider promises availability; keeping typed words and saved coordinates usable without either service is essential. Numeric throttles below are proposed app limits, not provider guarantees.

One product decision remains: the proposed automatic 3-character minimum prevents `西湖` and `外滩`, short queries that made the accepted Photon test succeed. Recommend keeping automatic suggestions at three characters, with explicit Search submission for one or two characters under the same quotas. Lead decides that exception or records the limitation.

## Published provider conditions, checked directly

- [Photon's public site](https://photon.komoot.io/) permits reasonable project usage, can throttle extensive use and gives no availability guarantee. Its [upstream README](https://github.com/komoot/photon#demo-server) additionally warns of blocking and changes without notice. The project supports search-as-you-type; Nominatim's separate public-service restrictions are not Photon's policy. No numeric safe quota was published in the sources read. A [maintainer response](https://github.com/komoot/photon/discussions/822) describes ordinary search boxes as reasonable and directs large geocoding batches to a private instance. Do not turn “Find places” into an unlimited public-Photon batch job.
- [OpenFreeMap's own site](https://openfreemap.org/) permits free embedded maps, including commercial use, with attribution. Its [terms](https://openfreemap.org/tos/), dated October 14, 2026, provide no warranties and allow discontinuation; normal integration is supported, while automated data collection is restricted. Optional offline area downloads have separate limits: 3,000 tiles or 50 MB per download, four concurrent requests and an identifying User-Agent. Offline tile downloading is not needed for this release. The software license does not replace these hosted-service conditions.
- [OpenFreeMap privacy](https://openfreemap.org/privacy/), dated October 8, 2026, covers embedded tiles. It says routine access logs omit IPs but retain request metadata; error logs can contain IP and URL, and security incidents can enable temporary IP logging. Cloudflare may process delivery requests. Browser-to-provider traffic therefore must not be described as anonymous or as sending only images.
- [OpenStreetMap's attribution guidance](https://www.openstreetmap.org/copyright) requires contributor credit and a link identifying the data license. Keep Jazz's search footer credit, and retain visible linked map attribution at both widths/full screen. [OpenFreeMap's integration guide](https://openfreemap.org/quick_start/) supplies MapLibre setup; preserve attribution when changing style or controls.

## Step 1: concrete Worker and editor checks for D15

1. **Authenticate before outbound work or cache lookup.** Search accepts the existing signed-in account, rejects signed-out/invalid-cookie requests and cross-site requests under the existing same-origin protections. No arbitrary upstream URL, path, headers or redirect target comes from the client. Photon HTTPS origin and `/api` are fixed; only validated query and optional chosen area are mapped to provider parameters. Do not forward cookies, authorization, IP headers, workspace IDs, page titles, notes or account IDs.
2. **Server-enforced limits as well as UI delay.** Start with at most 30 searches/minute and 500/day per account, plus 60/minute deployment-wide; these are conservative proposed app defaults to be set in shared configuration. Enforce across Worker instances, not a process-local Map. Bound pending work, return a normal limit message, honor provider 429/backoff, and avoid automatic retry loops. Cache identical account/query/language/area requests for five minutes; bound entries and retention. Do not log raw queries, coordinates or upstream request URLs in application errors/analytics. A short cache must not become stored search history.
3. **Bound and validate both sides.** Trim and bound query text (proposed maximum 256 characters), check finite coordinate ranges and allowed area size, cap returned suggestions (proposed five), use an abortable timeout (proposed five seconds), and bound response size. Validate provider JSON before producing a small app-owned suggestion object. Treat names/addresses as text, never HTML. Store no executable/provider-supplied navigation URL; generate maps links using approved templates and encoded values.
4. **Never lose input on service failure.** Error, malformed/oversized response, timeout, 429, offline and no matches keep the typed-name-without-pin choice. Abort superseded searches and ignore late responses. Do not search incomplete IME composition; do not let a late result overwrite typing, a committed selection, a different cell or a closed sheet. Retry is deliberate. Opening a sheet, reading stored Places and converting Place to Text perform no search.
5. **Current location is a distinct boundary.** Ask browser permission only after the explicit tap, with no location watch or background collection. A permission grant is not a blanket authorization to forward precise coordinates to search. Step 1 can store the selected coordinates with a local display name; if reverse geocoding is desired, name that provider transmission in the design and disclosure first. Denial/timeout leaves manual entry usable. Coarse bias is sent only when the user has chosen the relevant area; never silently derive it from workspace text.
6. **Durable values and rollback.** Name/address strings are bounded; coordinates are optional as a validated pair (latitude -90..90, longitude -180..180), with name-only values explicitly valid. Provider identity is metadata, not a requirement to read or open the pin. Test an actual old-code unrelated page write, a source property/view edit, type round trip and reload: the Place value must survive byte-for-byte where expected. Include `layout: map` in compatibility fixtures before Map ships; drawing alone is not proof against older-code rewrites.
7. **Step-1 network and cost proof.** An idle or ordinary day page must make zero Photon/OpenFreeMap requests and load no MapLibre code. Trace a synthetic search to prove the outbound fields, then mock failures and multiple concurrent accounts/Worker instances to prove limits. No provider is called by ordinary database display, export or type conversion. Native permission/keyboard/IME behavior remains a separately identified native check.

## Step 2: browser map boundary

MapLibre is bundled/self-hosted and loaded only for an actual Map view. The browser then exposes its network address and requested map area to OpenFreeMap/CDN; tiles can reveal viewed geography even without row titles. The release note must identify this separately from Worker-proxied Photon search and from user-initiated Apple Maps/OpenStreetMap links.

Use `credentials: omit` and a no-referrer policy for external requests, not workspace IDs in URLs. Keep map style/sprite/glyph/tile URLs on an explicit approved host set. Provider style JSON and its nested source URLs can introduce other hosts, so inspect the selected style and actual network trace before finalizing CSP; do not broadly allow all HTTPS hosts. Prefer a bundled MapLibre worker and account for worker CSP. Prevent offline/service-worker precaching of entire areas in this step. Pin labels remain local app text, not provider query parameters.

No style/host allowlist is certified by this review: fetching the public Positron style returned HTTP 403 in my environment. The terms pages were readable. Host/CSP verification remains a build-time acceptance check, not an invented list of hosts. Loading failure must preserve rows and show the specified unavailable state without repeated requests.
