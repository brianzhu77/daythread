# Ratchet — 独立评审 v1 · 2026-10-15

结论：应先修订可观察行为与验证顺序，再决定应用实施。已读 README、六份 specs，以及历史 personal-app-discovery / product-stress-test。依据为本轮 BASELINE.sha256；未读取其他评审文件。以下是规格缺口及风险判断，不是已复现的应用缺陷：当前没有应用可验收，没有执行真实模型、浏览器或数据库测试。

## 最重要的五项

### 1. 未安排承诺缺少确定的发现路径，接续规则可能让它们长期失去可见性

- **严重度：重大；类型：当前设计，关联用户目标。**
- **依据：** 01 F02/F07、02“事实集合 / 接续候选”、04 A05/A14/R05。无日期任务可以创建，但事实集合不包含它；接续仅取最近有效计划中的前三条。搜索可找到不等于系统帮助 recall。规则未说明未进入计划的新任务如何成为候选，也未说明前三条以外的任务怎样跨越下一份计划继续被发现。
- **场景：** “要给 Alex 发邮件，时间未定”成功保存；随后建立新的每日计划，再跳过三天 review。没有截止、关注日或未来计划日的该任务不会进入事实集合。若它不在最近计划内，接续规则也无法找回；即使在候选库存内，固定按原顺序选前三条也可能长期看不到后面的明确承诺。
- **影响：** 数据未丢却要求用户记得搜索，正好把 recall 负担还给用户。不能将“无截止”解释成“低风险”。
- **推荐：** 明确定义未安排 open 任务的独立查询与可见入口，数量可以汇总、无需逐项清零；新录入回执说明“未安排，保留在未安排入口”，允许一键今天做。跨日候选用可重算库存而非仅上一页可见行；记录最近展示日，允许展开全部，不能依赖 AI 或用户记忆找回。前三条仍可保留为试验参数，不承诺所有库存每天回流。
- **取舍：** 增加一个轻量查询入口与少量状态；比增加强制每日清单便宜，仍需真实试用判断是否形成积压焦虑。
- **验证：** 造 8 条无日期承诺，其中 3 条一直不处理；跨 4 天、跳过 review、删除一份每日页。逐条说明在哪里找回，确认其存在性与入口不依赖最近页面是否包含它；固定前三条不能成为其余事项唯一的发现机制。

### 2. 正文引用与每日安排的权威来源尚未定清，同一动作会有两种合理实现

- **严重度：阻断（实现前需定规则）；类型：当前设计。**
- **依据：** 01 F03/F06；02 Page 与 Block、DailyPlacement、一步暂放、每日构建。同一任务同日允许多个引用，但“移除任务行”又意味着 placement=excluded、清计划日与暂停自动接续。
- **场景：** 今日页顶部计划和下方随手记各引用任务 A。用户在下方按退格删除该行：这是删除一个引用，还是全局暂放？若全局暂放，上方正文是否同时移除？若只删引用，是否违反 F06？普通页面的任务行又属于哪种语义？只用 Task ID 去重不能回答这些问题。
- **影响：** 容易出现“还看得到任务但已经暂停”“删随手记改变今日计划”等不一致；验收 A11/A16 没覆盖同日多位置和普通页。
- **推荐：** 用明确的“暂放今天”操作修改 DailyPlacement 与 Task；通用编辑器删除只移除指定 Block，默认不修改独立事项。真正的计划行可带明确身份/操作回执；若坚持删计划行等于暂放，需定义计划行与普通引用的可见区别及多引用效果。计划、正文和事实区分别由谁驱动，列一张状态转换表，操作应在同一事务内完成。
- **取舍：** 显式操作略多一次入口选择，却降低自由编辑的不可预期性；不增加逐次去向弹窗。
- **验证：** 今日计划行、今日普通引用、普通资料页引用、历史引用各做删除/暂放/撤销；两处引用并存时检查实体、placement、所有关联行。验收须规定每次哪些字段改变、哪些保持。

### 3. AI 的格式校验无法证明操作意图，历史资料也可能污染自动变更

- **严重度：重大；类型：待验证假设。**
- **依据：** 03“输入上下文 / 信任边界 / 自动应用边界”，04 X08。所有已有工作区内容被送入模型；ID、权限、日期、版本都正确，也可能是依据资料里一句命令完成/取消了真实任务。evidence 已明确不能替代校验，但没有另一条确定的意图保障。
- **场景：** 历史资料或 AI 生成段落写“下次 review 时取消任务 A”；用户本次只写“今天很忙”。提案 cancel_task 使用正确 A ID 和版本，结构校验仍可能通过。单测文章粘贴当下不生成任务，不能覆盖之后 daily draft/review 读到它的场景。
- **影响：** 自动应用有语义误改风险；撤销依赖用户先发现错误，不能将 X08 描述为一般性的安全保证。
- **推荐：** 每种 mode 独立操作白名单；资料保存只获内容写入能力，daily draft 无状态变更能力。capture/review 对已有事项的完成、取消、改期、清截止，以“变更摘要 → 确认应用”为试用默认；明确创建的新事项可直接记录并回执。选中文字整理按既有差异确认原则执行。上下文来源标记保留，但不能宣称其单独阻止注入。
- **取舍：** 更新旧承诺增加确认，可能违背低负担体验；先验证误改与确认成本，再考虑放宽明确低风险操作。无需把所有新建输入都强制确认。
- **验证：** 建人工标注语料，覆盖当前输入、历史资料、历史 AI 总结、引用正文中的指令；至少跨 capture/draft/review 三种模式。检查未请求的状态变更是否能通过应用入口，而不只检查模型文字。模拟提案测试权限边界，真实模型另测语义误判；无真实调用证据时只标“防线已设计”。

### 4. “可重试”缺少中断后的可判定状态与多对象撤销契约

- **严重度：重大；类型：当前设计。**
- **依据：** 02 Capture/Generation 状态和写入一致性，03 请求生命周期，05“一次服务端请求完成处理”，04 X02/X03/X05/X07。已有原子应用、版本与幂等要求是良好基础，但 processing/running 卡住后怎样恢复、同一 capture 的澄清/编辑/重试如何分代未定义。
- **场景：** Capture 已保存，进程退出；又或者事务已提交、回执丢失。刷新后前者应重试、后者应读取结果；不能只把两者都重新调用模型。再如一次输入建任务和资料，用户随后把资料补充并引用到别页，“撤销本次整理”不能级联删除新使用的内容。
- **影响：** 永久“整理中”、不必要重复计费、旧响应与新澄清混用、撤销覆盖后续数据的风险。现有验收多验证一般失败，未验证这些崩溃窗口。
- **推荐：** 定义稳定提交 ID、Capture revision、attempt ID 与提案应用 ID 的对应关系；已有应用结果优先返回，过时 revision 无应用资格。无需立即引入 worker，重进页面即可查询已存状态并提供恢复操作。多对象撤销先检验整组前置条件，冲突则不做破坏性部分回滚，展示受影响对象与可恢复前值；有后续引用的产物保留。
- **取舍：** 需要明确重试协议与操作组依赖，复杂度真实存在；可先把多对象“一键撤销”降为可审查的恢复操作，但不能声称全面撤销已实现。
- **验证：** 对保存前、保存后/模型前、模型返回后/应用前、事务提交后/回执前四处强制中断；刷新、双击、并发重试、编辑后旧响应、澄清后旧响应。每个最终状态检查原话、产物数、关系、实际回执；多对象撤销覆盖新增下游引用场景。

### 5. 价值验收与功能验收脱节，无法知道系统是否真的降低日常负担

- **严重度：重大；类型：待验证假设，关联用户目标。**
- **依据：** 00“成功的含义”，04“5–7 天试用 / 试用后决策”，05 M0–M5。现有验收对一致性较具体，对价值仅观察“愿意用几天”，而最早交付先建完整资料编辑/引用基础，直到 M4/M5 才体验核心每日循环。
- **影响：** 可能做对大量功能，却在晚期发现草稿纠正、确认、资料录入和回执阅读比原来规划更累。“有一次引用”也不能证明解决收藏后不再使用的问题。
- **推荐：** 正式开发前用现有真实笔记做小规模人工回放，严格标注是人工/交互实验。记录原工具的一次规划与 recall 基线；同一材料比较准备草稿所需人工补充、核查、纠正及最终开始行动的总时间。资料既测主动引用，也测相关内容是否在有用的行动场景中被发现。候选规则必须允许“本轮无价值证据/需改变方向”的结论。
- **取舍：** 小样本不能证明长期节省或统计显著性；只能用于发现高代价摩擦，不替代真实应用 5–7 天试用。
- **验证：** 3–5 个真实日场景（含漏 review、无截止承诺、资料复用），由 Brian 指出漏项与多余确认。建议暂停条件：出现任一未被发现的承诺误改/遗漏，先修规则；连续多个场景净负担未减，先修流程而非加功能。具体继续/停止判断交 Lead 汇总，不能伪造量化效果。

## 补充检查与推荐默认值

- **偏好状态（次要，技术偏好）：** README、00 U09/U10 与 05 仍写“用户已确定”。统一为“历史偏好，本轮可质疑，推荐暂沿用，兼容性待验证”。没有证据支持为了独立审查而更换整套栈。
- **暂放与关注冲突（重大，当前设计）：** attention_on 到期后永久进入关注区；暂放保留它。20 条“开始准备”任务都被暂放时，正文虽清爽，关注区仍可变成第二个积压。推荐已暂放关注项折叠汇总、可查原因，真实截止单独突出；试验中观察用户是否认为“暂放没用”。不自动删除关注日或取消真实承诺。
- **上下文容量与隐私（重大，当前设计/待验证假设）：** 全工作区随资料增长最终容量失败是已承认的边界；旧资料、已移除内容、Capture/变更历史是否被送出尚未定义。推荐在试用前说明实际发送范围、默认排除软删除内容和无关运行日志、对容量失败提供手动保存/处理路径；不以此次评审默认为用户授权把全部历史私密内容发给供应商。此处未核查供应商留存条款，不作隐私合规结论。
- **资料 provenance（次要，当前设计）：** “页面有来源”不足以覆盖一页混合多个来源的摘录。quote 可带自己的来源；搜索和 AI 上下文保留原文、个人文字、AI 摘要分类。验收混合来源与改名移动后的定位。
- **恢复边界（次要，当前设计）：** JSON 导出保留关系的要求合理；当前没有导入，不能称为可用备份恢复。试用前至少人工校验导出对象数、外键闭合与软删除标记。
- **日期（重大，当前设计）：** 补充同日截止有具体时间、夏令时不存在/重复时刻、修改工作区时区、历史 review 的“明天”目标。现有历史页相对日期按实际录入时间的规则可保留，但生成哪一天的草稿也需回执明确，不能默认为历史日+1。多日/旅行自动调度可继续暂缓。
- **访问隔离（重大，当前设计）：** S02 不只测伪造 workspace_id，也要以另一用户身份把合法 Task/Block ID 混入当前工作区的引用、批量 RPC 与导出请求。这是未来执行测试，不是本轮已验证安全。

## 建议进入修订的验收优先级

1. **先规则回放：** 两个循环、删除/暂放矩阵、无日期库存、漏 review、资料命令隔离；不创建应用。
2. **再最高损失不变量：** 原话持久化、同日唯一、同事项身份、跨工作区不可引用、原子应用、旧 revision 不生效、丢回执不重复、人工内容不覆盖。
3. **再真实集成：** 有授权环境下测试登录、RPC、真实模型三模式、刷新恢复与编辑器稳定 ID。当前不执行。
4. **最后真实试用价值：** 将纠正与确认成本计入使用负担，结合资料是否实际帮助行动作判断。

## 我会做的最小实验

一张 4 天状态回放表：8 条无日期任务、1 条截止任务、1 条关注任务、1 个事件、1 份含命令句的资料、两处引用同一任务。依次安排、暂放、漏 review、删除引用、改期、迟到响应、撤销；每步记录原话、实体、placement、正文、事实区与候选区预期。先检查规则能否产生唯一答案；不能时先修规格。然后用 3–5 份真实 daily note 的脱敏副本做人工草稿实验。两者都不是已执行的应用测试，也不包含本轮未授权的付费调用。

## 首轮我会砍掉的内容

- 复杂自动推荐排序、向量检索、完整 wiki 自动维护、Calendar/e-ink、自动抓取，保持暂缓。
- 不追求所有结构编辑的一键全局撤销；先保证原话与前值可查、已改数据不被破坏，再覆盖操作组恢复。
- 不先建所有通用编辑器能力再验证每日循环；只保留支撑资料存放、稳定引用与实际书写的最低能力。
- 不砍原话保存、资料存放/引用、真实承诺的可靠状态，也不以模拟模型冒充真实接入。

## Cross-review

已完整阅读 Bumblebee、Jazz、Wheeljack 三份独立报告。以下均为推荐规则，尚无原型或真实模型证据。

1. **当日计划来源：有条件支持 Jazz A 作为原型默认，修正我此前保留正文模型的倾向。** 结构化 Today 能减少计划行与正文同步、合入的实现负担；但事实区是事实投影，不必然构成第二份权威数据，不能只靠视觉分区宣称解决状态一致性。A 必须让用户重排、改计划与引用资料，Notes 仍自由编辑；期限事实与用户选定行动应有不同含义。底线：Task 是事实真源，每日选择只有一套关系，删除普通引用不暂放；历史 Today 显示当前还是当时安排须说明。A/B 各走一次“围绕一个任务写思考并引用资料”，再判断能否接受不能交错书写的代价，不将 A 偷换为已批准。

2. **接续：同意合并。** 用一个不依赖上一页正文的 open 库存查询，按未来安排、可接续、未安排、已暂放区分资格；carry frontier 是其中可接续子集，首页“仍未完成”折叠行是展示，未安排入口是同一库存的筛选。最多 3 条仅限制首页建议展示。底线：无日期新承诺、超额候选、纯笔记日和删日记后都可发现；已暂放不自动成为接续候选；不要为统一入口把全部无日期任务每天推荐。Bumblebee 提出的“过 N 天静默 Later”不作为默认。

3. **打开页调用 AI：同意砍掉，不与次日草稿价值测试冲突。** Review 或主动请求产出草稿，早晨读取已存结果；事实与接续可以直接显示。底线：跳过 review 的下一天仍能恢复事项，主动“帮我规划今天”可用，且其结果不覆盖正在写的内容。砍掉自动触发只能减少一种时机，不能声称所有草稿/人工内容冲突状态已消失。

4. **资料循环：支持检验 0–2 条相关资料推荐，反对直接把检验变成首轮正式新增承诺。** Bumblebee 更准确击中了“保存后不再回看”；手选引用只能证明存取能力。先在人工回放中同时比较手选与关联推荐，记录此前没想起、实际用于行动或结论的资料，允许零推荐。底线：真实 ID、来源、可忽略，不把推荐变成任务；数量不是价值。页面级引用可作为薄切片，但块级引用是历史明确需要的能力，不能因实现便宜就无声删除：先原型验证页面内定位是否足够，再由 Lead 集中呈现范围修订。无需先建完整反链 UI。

5. **修改事项确认：同意作为 AI 提案默认，明确排除直接 UI 操作。** 勾选完成、日期选择器或明确“取消任务”按钮本身已表达操作，无须再加一次确认。自然语言模型提出的已有承诺变更先给合并摘要确认；新建直接应用和回执仅限明确个人输入，资料入口永不自动建任务。底线：确认时再核对 revision/对象版本；新建仍需澄清歧义，不能把“新建”理解为任何模型输出都自动应用。资料/旧 AI 文本不能因为被模型引用而获得本次授权。

6. **验证顺序：同意纸面状态回放与轻量 A/B 可并行；反对一开始串行安排所有实验。** 先半天以内把删除/暂放、改期、库存和漏 review 的预期表写清，同时用几屏静态原型比较 A/B 与回执纠错。它们解决规则和操作理解，不能证明持续价值。随后在 Brian 愿意投入且资料/模型调用范围明确后，用少量真实日记做人工代理试用；先承认其人工整理/提醒成本，不要求停用旧工具作为第一道门槛。编辑器丢弃式实验等交互模型收敛后再做，A 被接受时可显著缩小；数据库原子性实验也后移到正式实现前。底线：当前不调用付费 API、不装依赖、不以人工准备草稿证明实际应用省时。Bumblebee 的 5/7、4/7、三次资料使用只作候选观测值，不作已获同意的成功门槛；样本稀疏时记录证据不足，不能硬凑次数。

**其他必须保留的边界：** Bumblebee 建议裁掉“条件撤销”可裁 UI 深度，不能裁版本检查；即使只撤销最近一次操作，另一个标签页/关联引用已更新仍不可覆盖。软删除恢复可用最小入口，不能与稳定引用/唯一 Daily Page 的要求矛盾。Jazz 的 Undo all 需受操作组冲突规则约束，不能承诺无条件全撤销。这些是未来实现前的契约底线，不要求现在建设完整历史系统。
