## 1. 目标、偏好与模型权限

自然语言录入、引导review与每日建议服务于减少规划和recall负担。OpenRouter + OpenAI GPT沿用历史偏好；完整模型ID和路由在实现时核对，不采用未经核对的“最新”别名。保留真实模型调用，模拟只作一致性/故障验证。

模型只生成受限提案，不能直接访问数据库、执行代码、抓网页、发通知、设置预算或更改工作区配置。数据权限、日期事实、接续资格和预算准入由应用决定。

| 入口 / mode | 可提出什么 | 应用规则 |
| --- | --- | --- |
| capture：本次用户表达 | 新建任务/事件/记录/资料；引用；提议修改已有事项 | 明确纯新建组可直接应用并回执；歧义/多行粘贴先澄清或预览；已有事项变更先确认 |
| 引导review中的任务动作 | 用户直接勾选、改期、Not today | 明确UI操作直接提交，不额外调用模型或再确认 |
| 引导review中的capture | 与全局capture相同 | 走同一提案、确认、幂等协议，不另建第二套review变更引擎 |
| review反思文字 | 保存原话；可供草稿作已标来源的背景 | 不解析为任务操作；需要调整走capture，不能因感受或文章命令改承诺 |
| daily_draft：review后/主动Draft my day | 建议文字、已有事项/页面引用、建议Top3、0–2资料候选 | 无任务/事件实体创建、状态或日期更新能力；选择建议后应用走明确UI操作 |
| Pages / Good Stuffs / 明确保存资料 | 保存文字、来源、摘录、个人备注和资料身份 | 不隐式生成个人任务，不调用可执行事项操作 |
| 明确Turn into tasks | 对用户选定内容产生创建提案 | 走capture预览；不因资料被读入上下文而自动触发 |

Good Stuffs里的链接或明确“保存资料”才建立资料身份；capture中只有一个URL视为明确保存链接。任务句中的URL只保留为该任务来源，Notes普通链接只是文字；模型不能自行把任意任务链接升级为资料。资料身份不等于推荐资格，“不再推荐”是显式标记，不靠URL猜购物用途。普通正文编辑、链接保存和今日页打开均不隐式调用模型。

## 2. E1：当天索引与完整关联上下文

Brian的D-C是当前输入方向：“当天note是索引页，抓到所有关联context”。以下是团队将“关联”落成可审计集合的默认定义，不声称用户逐条指定了图遍历算法。

### 请求身份与根

每次请求记录 workspace、mode、request_id/attempt_id、capture_id/revision（有则必传）、captured_at/解析时区、active_page_id/date、明确目标日、根页面与对象版本、来源类别及本次输入。相对日期依录入时刻而非历史页日期或响应时间。

根集合为：当前note全文、本次已保存capture或review原话、该日应用计算的Task/Event事实和接续候选（即使未合入正文）。本地未保存文字仅在用户明确本次提交时作为输入，并标明尚未写入Page；不能假装数据库已更新。用户查看旧日记时，根日期和草稿目标日分别明确显示。

### 展开与完整性

1. 沿根中的显式站内引用展开Page/Block、Task/Event及其直接来源；引用资料时纳入完整来源页并附目标定位信息。继续跟随这些页的显式出边，直至没有新节点。
2. 用工作区+稳定ID维护visited、节点和边，循环不重复展开。去重不能删正文语义；不按模型主观相关度筛掉已关联内容。
3. 不遍历全部反向引用，不将语义“可能相关”或所有历史Capture/Change日志自动纳入。未关联资料候选见E2，使用不同清单。
4. 权限先过滤/校验；任何跨工作区目标不能读取或发送。软删除目标只列已移除占位，不偷读旧正文。无法访问的目标在manifest标缺失，不能声称已完整收到其内容。
5. 外部URL没有已保存正文时仅传URL和“未提供正文”；不默增抓取或编造摘要。存在本地关联资料页才纳入其全文。
6. 保留版本快照：根、节点、边、每份内容revision及source类型（本次指令/历史记录/资料原文/个人备注/AI总结）。模型输出的evidence不能替代授权或版本校验。

发送前可查看manifest：完整关联正文清单、额外候选清单及各自模式、缺失/已移除目标、模型ID、规模与预算状态。界面说“已展开全部可访问显式关联内容”，不能夸为“掌握全部相关历史”。

### 容量失败

全部展开、输入预算和输出预留在发送前完成。完整E1正文超过所选模型窗口或费用上界时，不发送；保留输入、说明规模与原因。默认不静默截断、摘要、限深、拆成多次调用或自动换模型。用户可明确缩小本次范围，manifest标“范围受限”，不能继续称全量。缺失正文与容量失败是不同状态。

## 3. E2：未关联资料找回与模式边界

首切片以过去Good Stuffs中已保存且允许重访的资料为优先候选；用户另行带入的种子集可选，不把10–20条作为开工门槛。不是整个私人资料库默认外传；候选集与发送范围可见。用户标记“不再推荐”者不作为候选，不根据域名猜测购物用途。

- **已关联资料：** 始终属于E1全文，不能被本节降级规则替成目录。
- **额外未关联候选：** 有限试用集默认全文（原建议规模10–20份，不保证该数量一定装得下）；与E1清单区分、ID去重并共同计入窗口/成本。
- 若额外候选全文使请求超窗，可切换这部分为标题+用户备注目录，界面明确模式改变。它只用于发现线索，模型不得声称读过候选正文；推荐写“可能有用，打开看看”。用户打开/选入后，后续请求才按E1关系纳入全文。
- E1本身已经超窗、目录仍超窗或费用检查不通过时仍不发送。不能通过删减已关联正文来容纳更多推荐候选；预算不足不能自动绕过E3。

每日最多0–2条建议，指向真实资料ID，带一条有依据的使用原因；目录模式的原因只能依据标题/备注，不制造原文论点。推荐可为空、可忽略，不自动变任务、不擅自写入用户正文。首切片页面引用只打开原页；要保留原句使用quote附来源，不冒充动态段落引用或稳定锚点。

试用分别记录shown/opened/实际用于行动或结论；无机会记证据不足。有真实机会仍持续无用时降级，不因未点击就宣称资料本身没价值。

## 4. E3：每天10 USD的准入、预留与对账

用户上限为10 USD/day。团队默认以工作区America/Vancouver自然日计费归属，UI显示时区与重置时刻；不是每天花满目标。模型调用、失败但已计费的attempt、重试、草稿和capture共享同一上限；不将托管、邮件或充值手续费混称模型成本。

### 准入与结算

1. 服务端账本为工作区共享，MacBook/iPhone不能各有10USD。先查询该操作已提交结果，已完成请求重放不再调用或预留。
2. 每个真正的新attempt在数据库事务内预留：`settled + reserved + 本次保守费用上界 <= 10 USD`。首切片同工作区最多一条付费调用在途，幂等键防重复预留。
3. 保守上界需覆盖选定模型/路由的输入、明确max_output_tokens和可能的推理/额外计费，不将缓存折扣当保障。价格来源、检查时间、输出上限与计算依据留可审计记录；价格过期或计费上界不明则暂停新调用，不能用点估计承诺硬上限。固定模型/允许路由，不自动转更贵路由。
4. 网络发送在事务外；完整响应后按实际账单口径的usage成本结算，释放差额，保留provider generation/attempt ID。不能把上游推理成本当最终账户总扣费。
5. 超时、断线、进程失联或费用未知时保留预留并对账；不因客户端离开就退款。使用供应商generation ID等查询恢复（有可核对ID时）；无法确定费用则保守阻止后续调用，人工核对后解锁，不自动重复烧预算。
6. 发起日为账本归属日，跨午夜的在途attempt继续占原日预留，不能切日丢成本；供应商账单日期另留字段。同一付费在途限制及未知费用阻止规则跨日有效。更改工作区时区不能重置已有当日费用，首切片预算时区固定，变更需明确迁移。
7. 已预留但确定未发出的请求可以安全释放，仍记录原因；已发送未知结果不能按此处理。若发现实际费用超出预留，停止后续调用、记录差异并修上界规则，不能回写伪造的低费用。

### 超限与供应商限额

预留失败或预计超过剩余额度时不发请求，原话先保存；UI显示已结算/预留/剩余、重置时刻及手动重试入口。普通写作、任务动作、人工review保存继续工作，不半夜自动重试，不自动升限或减少E1上下文。

使用专用OpenRouter key的USD daily limit作为第二层兜底，不代替本地账本：官方接口的daily reset在UTC午夜，而不是Vancouver午夜。[OpenRouter API key限额](https://openrouter.ai/docs/api/api-reference/api-keys/create-a-new-api-key)（2026-10-16独立查阅）。供应商限额、余额/限流错误应与应用日预算耗尽区分。

官方返回usage包含账户cost，并可按generation ID查询用量，作为结算/对账依据；当前只是文档核对，没有真实扣费验证。[OpenRouter Usage Accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting)。正式调用前验证所选模型/路由实际计费字段与货币口径；没有可靠上界就不调用。

## 5. 提案验证、确认与事务

应用schema是协议真源；前端、服务端校验和模型JSON Schema由其派生。每个mode各有操作/字段白名单；daily_draft夹带状态更新直接拒绝。schema、ID、同工作区、真实日期、目标版本与输入revision都由服务端检查，结构正确不等于意图正确。

新对象用temp_id，App分配真实ID；组内引用必须可解析。update必须提供实际target_id、expected_version、修改字段与本次输入依据。未提供字段不改，null才清可空字段；未知update不能降级create。感受、条件、转述或资料里的命令不构成自动承诺。

- 需要澄清时整组不执行；保留原Capture、保存补充并递增revision，不另建重复任务。
- 明确纯新建组可直接提交并给可编辑回执；多行粘贴先预览。已有事项变更统一内联Apply/Edit/Discard。
- 同Capture有新建与已有修改时**整组等确认**，包括temp_id依赖；一个apply_key/事务提交。未确认新对象不存在，不能显示已保存。
- `needs_confirmation`持久跨日，Today显示待确认录入入口；Discard整组不应用，原话保留并标discarded、退出计数。重新整理显式新revision。
- 一旦已进入待确认，Edit删去全部已有修改、只剩新建也不自动提交。proposal_revision递增，仍需Apply；确认绑定新revision，旧确认不可重放。
- 直接UI勾选/改期/Not today是明确操作，不额外二次确认。正文整行删除的动作映射由01/02规定，不由模型推断；普通引用删除与历史呈现删除不改Task。

事务一次检查当前输入revision、proposal_revision、实体版本/权限、幂等记录，并关联写入Task/Event、placement、引用、Change和实际结果。模型请求不占数据库事务。

## 6. 身份、重试与人工内容保护

`capture_id`固定；原话编辑/澄清递增`capture_revision`；一次外部调用对应`attempt_id`、lease和独立预算预留。旧revision返回不得应用。租约到期只表示可恢复状态，不证明没有在供应商计费；需同时满足E3准入/对账才可发新attempt。

`apply_key=capture_id+revision+mode`唯一绑定不可变输入摘要。合法Edit只改proposal_revision，不触发“同key不同输入”拒绝；首次提交冻结最终提案摘要，后续同key返回既有结果，不按新提案重新写入。input摘要变化须新revision，不能复用key。

主动Draft my day无Capture时，Generation request_id+目标Page/date+输入版本有独立幂等身份。相同请求重试优先返回既有结果，新主动生成新request；每次真调用都有attempt与费用。模型基于E1快照生成，应用检查目标Page结构版本和依赖实体版本；旧结果可留待核对，不能覆盖新编辑。

已生成状态来自Generation，不从正文空白推断；删光模板不自动再生。模板默认Top3/Other/Events/Good Stuffs/Notes，用户可改标题、增删分区和在任意位置书写，AI不能恢复已删标题。Top3建议不等于已安排；只有用户明确选择并保存安排后才显示“N已安排”。事件无明确时间不得编时间。

任务Keep沿用同一Task身份；用户带到今天的普通Notes/Good Stuffs文字复制并附来源，属于明确操作，不由AI自动复制全部笔记。交接可以整体跳过/部分处理；未处理项不因用户跳过而变完成、取消或暂放。候选资格与数量由02规则算出，模型不拿库存自主重排承诺。

多对象Undo检查整组版本/下游引用，任一失败不破坏性部分回滚；编辑器Undo不越权回滚其他设备的实体状态。

## 7. 引导review与可降级运行

review保存自己的动作/录入/反思后为`review_saved`；目标日草稿结果为`draft_ready`，分别记录。额度/容量/模型失败是系统失败，不是用户没review；保存成功的人工review可结束，稍后主动重试草稿。第2步capture整理仍可调用模型；每日草稿调用在最后一步。纯反思永不隐式变更事项。

提醒采用获准的iOS重复提醒链接，由系统安排而非模型发送。模型失败不影响打开review。App可记录review链接打开与页面动作，不能声称能观察iOS提醒实际弹出/阅读；真实到达由设备检查与试用日志验证。

## 8. 接入及待执行验证

服务端沿用OpenRouter Chat Completions、严格JSON Schema及所需路由能力约束；具体模型/路由支持需在接入时核对，不静默降为文本解析。密钥仅服务端；正常数据读取用用户身份/RLS，同工作区引用约束不因模型上下文而绕过。私人全文、凭证和第三方日志不复制到运行日志；日志保留请求身份、阶段、用量与错误类别。

| 检查 | 最低预期（均待执行） |
| --- | --- |
| E1环/共享节点/无权限/悬空引用/URL无正文 | manifest和正文与预期逐项一致；不泄漏权限外内容、不假摘要；超窗发送次数0 |
| E2关联全文+额外全文/目录 | 只有额外候选可降级；显示模式；目录推荐不声称读过全文；用户排除者不推荐 |
| E3两设备各6USD、已用9.8+上界0.3 | 同时只受理一个在途；后者发送次数0；共享账本不突破10 |
| E3超时/失联/跨午夜/未知cost | 预留不丢、不自动退款/重试，原日归属可查；对账后再准入 |
| Capture纯新建/混合Discard/Edit/并发Apply/丢回执 | 对象只提交一次；混合组未确认不先建新项；旧确认/旧revision不能应用 |
| review保存成功、草稿失败 | review_saved仍成功、draft_ready未成功；手动重试只重生草稿，不重放事项 |
| 20条语料重复两次 | 明确/歧义/否定/条件/转述/历史资料命令/同名事项，分别记录模型提案与实际应用；不以schema通过当意图正确 |
| 手机/电脑编辑期间旧草稿晚返回 | 既有文字/安排不被覆盖；目标日、保存状态与发送范围回执真实 |

真实模型语义、数据库原子性/访问、预算账单、设备行为和使用价值是不同证据；纸面回放/官方文档不能替代上述运行检查。具体验收编号由04对应维护。
