# 00 · 范围与决策

## 产品目标

让用户每天从一份已准备好、可以自由修改的 daily note 开始，减少回忆、重复整理和翻找资料的消耗。资料和事项持续存在，每日页面串起它们。

第一轮服务单个用户的真实试用。验证功能循环和可预期性，不以推荐准确率、全自动知识库或编辑器功能数量为目标。

## 用户已明确的约束

| ID | 内容 |
| --- | --- |
| U01 | 独立 Web app 可以，不需要 Notion 数据迁移或同步，允许手动带入信息。 |
| U02 | 保留自然语言输入；输入和已有信息直接交给 AI，首版不优化提示词、检索或上下文。 |
| U03 | Home 是每日主入口，提供包含行动安排的 suggested 自由书写页，内容可以修改。 |
| U04 | 需要未来事项在对应日期/临近日期返回 daily note。 |
| U05 | 需要 review 与次日计划衔接，减少每日规划、recall 消耗。 |
| U06 | 不希望移出今天后积压成需要维护的巨长清单，不希望每次移除都选择去向。 |
| U07 | 需要 Pages/Blocks 保存手动收集的资料，daily note 可以引用；自动抓取可以暂缓。 |
| U08 | 长期希望 Calendar、e-ink/TRMNL、Top 3、提醒和资料重访；首轮范围需要保持低成本。 |
| U09 | 用户已选择 OpenRouter API，首版使用 OpenAI GPT 系列模型；具体版本尚未指定。 |
| U10 | 用户已确定前端使用 TanStack Start + TypeScript，数据使用 Supabase。 |

## 首轮必须具备

1. 每日页：按本地日期创建唯一页面，提供可编辑初稿，保留历史。
2. 自然语言录入：保存原始输入，提取任务、事件、笔记和明确日期，给出可纠正回执。
3. 普通页与基础 Blocks：创建、编辑、排序、保存与查找手动收集的内容。
4. 页面/Block 引用：在 daily note 及普通页引用，点击定位原内容，查看反向引用。
5. 事项处理：完成、改期、取消、一步暂放、撤销，跨视图保持同一事项状态。
6. 日期回流：计划处理日、准备关注日、截止日与事件发生日可以分别表达。
7. Review：通过一段自由输入回顾和调整，生成明日草稿；跳过一天也可继续使用。
8. 简单未来事项列表与暂放找回入口，不以完整 Calendar 为前提。
9. 可靠持久保存、错误可见、重试不重复、基本导出。

## 首轮明确暂缓

- Notion/外部日历双向同步、历史批量迁移。
- 自动网页抓取、视频转录、完整仓库分析、附件管理与 PDF 导入。
- 自动跨来源维护完整 Wiki、知识图谱、长期个人画像、向量检索、多 agent。
- 完整月/周 Calendar、日历拖拽排期、TRMNL 专用接入。
- 多人协作、通用数据库视图、多层 Block 嵌套、复杂排版。
- 重复事项规则、多日事件及跨时区旅行自动调度。
- 页面关闭后的后台生成、主动推送及系统通知。

主动提醒仍是长期需求。首轮只验证打开页面后出现的提醒与 review 提示，不能据此宣称验证了“系统主动把用户叫回来”。若试用被忘记 review 阻断，优先加入一条真实提醒渠道。

## 为实施而提出的试验默认值

下表是本版规格采用的明确默认值，不代表用户逐项选定；修改时同步交互、数据和验收。

| ID | 默认规则 | 原因 |
| --- | --- | --- |
| D01 | Daily note 与普通资料都用 Page；正文由有持续 ID 的基础 Blocks 构成。 | 同一套保存、编辑与引用机制。 |
| D02 | 任务/事件有独立身份，页面中的任务/事件块是其呈现位置。 | 跨日不复制，移除引用不会丢失事项。 |
| D03 | 普通正文编辑只保存文字；点击录入提交或“整理这段”才触发 AI。 | 避免感想、原文和日记被误当成操作。 |
| D04 | 用户明确表达的待办直接建任务；AI 自行提出的新行动先保留为建议文字。 | 不让推荐变成承诺。 |
| D05 | 今日暂放不弹选项，停止自动顺延，不清除截止日期；未来明确日期仍有效。 | 减少操作，并防止失去重要约束。 |
| D06 | 昨日未完成可以成为次日草稿候选，非期限候选默认最多 3 条；不自动给全部旧任务改计划日。 | 检验低负担接续，避免无限搬运。 |
| D07 | 首次进入日期页生成草稿；已有文字不被后台重写，新事项以更新提示呈现。 | 保持页面可编辑且可预期。 |
| D08 | 页面与段落引用默认显示当前内容；历史页明确标注关联事项显示当前状态。 | 避免把动态引用误当成历史快照。 |
| D09 | 显式截止事项可在日期页外的“需要留意”区域出现，不受今日暂放或候选条数限制。 | 保护期限，同时允许正文自由编辑。 |
| D10 | 对无准备日期的任务不擅自推算提前几天；先按明确日期展示。 | 首轮减少猜测。 |
| D11 | 工作区默认采用用户本地时区，试用起始可设为 America/Vancouver。 | 日期解析和每日页面保持同一基准。 |

“最多 3 条”只适用于非期限候选，是可调整的试验参数。完整内容可展开；真实截止和固定安排不得因数量限制被静默隐藏。

## 成功的含义

功能正确：记录不丢，日期回流正确，完成/改期/暂放一致，资料确实能保存并引用。

使用有价值：用户愿意连续几天用它开始和结束一天，较少回旧工具找事项，且至少有实际资料引用帮助行动或思考。机会不足时延长试用，不用纯点击量替代价值。

## 不作为本轮承诺

- 不宣称完全理解任何任意文档改写或模糊语句。
- 不宣称能自动清除真实承诺超出时间容量的问题。
- 不把“保存了很多资料”视为“资料已被有效复用”。

## 实施前仍需确定

TanStack Start + TypeScript、Supabase、OpenRouter 与 OpenAI GPT 系列已确定。实施前仍需配置 Supabase 项目、试用登录方式、具体模型 ID 和服务端凭证，确定应用运行位置及常用设备；不得以模拟回复宣称完成 AI 接入。首版仍为单用户试用，建议用最小 Supabase Auth 登录和工作区访问规则，不扩展成多用户协作产品。技术方案见 [交付文档](05-delivery.md)。
