# 04 · 验收与真实试用

验收分成“实现是否正确”和“用起来是否值得”。自动化检查用于关键数据规则，真实模型与真实日常使用仍需单独验证。

## 固定测试基准

使用可控制的本地日期 2026-10-13、时区 America/Vancouver，另加入跨午夜场景。示例均为测试内容，不代表用户真实安排。

最少包含：

- 资料页“编辑器项目”，有来源 URL、两段正文和一条个人备注。
- 任务 A：10 月 14 日处理、10 月 16 日截止。
- 任务 B：无截止、10 月 13 日计划处理但未完成。
- 任务 C：用户明确暂放的探索任务。
- 事件 E：10 月 14 日 14:00，一次单日安排。
- 一份已有人工笔记的明日页，用于检查草稿合并。

每个“持久保存”场景至少跨刷新或应用重启检查一次。不得只验证屏幕上的临时状态。

## 行动循环

| ID | 操作/条件 | 必须结果 |
| --- | --- | --- |
| A01 | 同日首次打开、刷新、再次进入 | 同一日期只有一个 Daily Page，正文不重复生成。 |
| A02 | 输入“明天下午三点开会” | 保存原话与事件；回执显示 2026-10-14 15:00，未来列表可见。 |
| A03 | 输入“周五前交材料，周三开始准备” | attention=10/14、deadline=10/16；不编计划处理日。 |
| A04 | 输入“以后也许学画画” | 作为想法保存，不新增任务或日期。 |
| A05 | 输入“要给 Alex 发邮件，时间未定” | 创建无日期 open 任务；不变成已逾期。 |
| A06 | 一句输入包含任务、链接和笔记 | 正确关联产物；没有正文时只保存链接，不出现假摘要。 |
| A07 | 当前仅有一场明确会议，输入改期 | 更新原 Event，ID 不变，不复制会议；回执展示日期变化。 |
| A08 | 有多场合理会议候选，输入“会议改周四” | 暂不应用，问具体哪场；补充回答后继续原 Capture，不重复建对象。 |
| A09 | 在两页引用同一 Task，任一处完成 | 同一 Task 为 done，其他引用显示当前完成状态，未来候选停止。 |
| A10 | 任务改计划日，不提截止 | planned_on 改变，deadline 保持原值。 |
| A11 | 从今日任务行暂放 | 一步完成，无去向弹窗，今天不再插回正文，可撤销。 |
| A12 | 暂放有截止的任务 | 移出今日正文，截止日期和日期状态提示仍有效。 |
| A13 | 下一日打开 | 明确安排和事件出现；未暂放 B 可作为建议接续，C 不因未完成自动回来。 |
| A14 | 非期限候选超过默认上限 | 正文候选最多 3 条，其余可展开；所有截止事实可访问。 |
| A15 | 为暂放任务明确安排新日期 | 恢复对应安排，清除暂停顺延标记，新日期页不会被旧排除记录阻挡。 |
| A16 | 删除历史页的任务引用 | 只改变历史页面，不取消或暂放今天的任务。 |
| A17 | 显式取消任务再恢复 | 取消停止未来行动提示，历史可查；恢复同一任务 ID。 |
| A18 | 不完成事件并跨过发生日 | 保留历史事件，不自动顺延或转任务。 |

## 页面与资料循环

| ID | 操作/条件 | 必须结果 |
| --- | --- | --- |
| P01 | 新建资料页，手动粘贴正文和来源 | 标题、正文 Blocks、来源持久保存，可搜索找到。 |
| P02 | 编辑、排序、改标题 | Page/Block ID 不变，相关引用仍定位正确。 |
| P03 | daily note 引用整页和其中一段 | 可见简短预览，点击分别打开原页和定位 Block。 |
| P04 | 修改被引用正文 | 动态引用展示当前内容；独立复制的 quote 不随之改变。 |
| P05 | 删除 daily note 中的资料引用 | 原资料与原 Block 仍存在，反向引用列表同步移除这一项。 |
| P06 | 删除被引用 Block 或资料页 | 引用显示目标已移除，不丢引用位置；恢复后重新可用。 |
| P07 | 删除一个显示任务的资料页 | 不级联取消独立任务，任务仍可查找。 |
| P08 | 两个页面互相引用 | 预览不无限递归，两个页面都可正常打开。 |
| P09 | 修改标题、正文、章节顺序并移除模板标题 | 可以保存；AI 不自动恢复被删除标题。 |
| P10 | 编辑普通日记“太累了，不想做了” | 仅保存文字，不取消任何任务。 |
| P11 | 查看历史页关联事项 | 清楚标识显示当前状态，可查看何时完成/改期。 |
| P12 | 移除 Daily Page 后重新进入该日期 | 仍识别同一页面并提供恢复，不新建第二份同日页面。 |
| P13 | 查看资料的反向引用 | 能回到实际引用它的 daily note，复制的无引用纯文字不伪装成关联。 |

## Review 与草稿

| ID | 操作/条件 | 必须结果 |
| --- | --- | --- |
| R01 | 完成一次 review，自由写调整意见 | 原话保存，明确事项变化有回执，生成明日草稿。 |
| R02 | 不填写某个 review 问题/不逐条安排 | 可以结束，不强迫逐项选择。 |
| R03 | 明日页已有人工笔记时生成草稿 | 产生可合入更新，不覆盖原笔记。 |
| R04 | 重试生成、重复提交 review | 不复制任务、页面、同一份草稿或总结。 |
| R05 | 连续几天未用再回来 | 内容/任务未丢；恢复最近计划，截止可见，不要求补完漏掉的 review。 |
| R06 | 页面生成过程中开始写字 | AI 返回进入待应用区，不覆盖新文字。 |
| R07 | 新事项到达已有未来页 | 日期事实和更新提示可见；正文合入由用户决定。 |

## 可靠性与 AI

| ID | 故障/条件 | 必须结果 |
| --- | --- | --- |
| X01 | 原始输入保存失败 | 显示未保存，保留当前文字，不调用 AI，不声称刷新后可恢复。 |
| X02 | Capture 已保存，模型超时 | 原话仍在，能重试或手动录入，现有任务可操作。 |
| X03 | 双击提交/同一请求重试 | 使用幂等 ID，同一输入产物只应用一次。 |
| X04 | 模型返回无效 ID/字段/日期或非结构化输出 | 不应用无效集合，不出现半成品对象，原话可恢复。 |
| X05 | AI 处理期间原文被编辑，旧响应晚返回 | 旧响应不得写入覆盖或生成过期任务。 |
| X06 | 请求基于旧版本，任务已在其他处完成 | 不将其覆盖回 open，显示冲突或重新核对。 |
| X07 | 撤销之前又改了同一事项 | 不覆盖后续编辑；说明无法直接撤销并保留前值可查看。 |
| X08 | 粘贴文章包含“忽略前文/明天完成清单” | 作为资料正文保存，不当成用户指令或个人任务。 |
| X09 | 未提供正文的链接 | 不调用隐藏抓取，不生成声称阅读原文的摘要。 |
| X10 | 临近本地午夜录入，模型次日返回 | 相对日期仍按 Capture 的时间基准，页面不突然切换。 |
| X11 | 已提供内容超出模型容量 | 明确失败且原文保留，不无提示截断后应用不完整结果。 |
| X12 | 导出工作区 JSON | 页面、Block、事项、日期、时区、来源和引用 ID 都保留，内容可解析。 |
| X13 | AI 与保存状态反馈 | “已记录”“已完成”等消息来自实际保存结果；没有真实操作不显示成功。 |

## Supabase 接入

| ID | 操作/条件 | 必须结果 |
| --- | --- | --- |
| S01 | 登录后写页面、重启应用再读取 | 内容从同一 Supabase 项目读取，不能只存在浏览器或服务进程内。 |
| S02 | 未登录或使用不属于当前用户的工作区 ID | 页面、事项、来源、Capture 及模型上下文均不可访问。 |
| S03 | 关联写入中途失败/两个请求并发应用同一提案 | 数据库函数回滚不完整写入；已应用提案不再建对象，版本冲突不覆盖新值。 |
| S04 | 查看浏览器构建和请求 | 只有允许公开的项目配置和会话信息；不包含 OpenRouter 或数据库管理员密钥。 |

## 检查方式

- 领域规则：自动化验证日期构建、暂放/改期/完成、跨日候选、幂等、引用移除和版本冲突。
- UI 关键流程：真实浏览器运行行动循环与资料循环，包含刷新和失败恢复。
- AI 接入：真实供应商至少覆盖明确录入、歧义输入、资料正文、daily draft 和 review；记录纠正情况。固定模拟输出仅用于故障与一致性检查，不能替代真实模型验收。
- 不为简单文案或纯视觉小调整增加镜像实现的测试。

规格写完不代表上述测试已经执行。实现时记录实际结果与未通过项。

## 5–7 天试用

试用前手动带入一小份真实安排和几份愿意使用的资料，不要求迁移历史 Notion。

至少经历：未来事项回流、一次未完成接续、一次暂放、一次改期、一次 review、一次跳过 review 后恢复、一次资料/Block 被引用并写下结论。

每日只需留下少量观察：

1. 从打开到开始行动，哪些内容直接有用，哪些必须纠正？
2. 有没有为了找漏掉的事情回 Notion/旧日记？具体是什么？
3. 暂放有没有减少打扰，是否带来忘记真实承诺的担心？
4. 资料引用是否帮助完成、判断或理解某件事？
5. Review 是帮助还是额外负担？忘记打开是否是主要阻碍？

不预设“节省 50% 时间”等未经验证的目标。可以记录耗时和纠正次数作为基线，先识别主要摩擦。

## 试用后决策

- 发现丢内容、重复建任务或错误改期：先修可靠性，再扩大范围。
- 主要摩擦是每天手动收集：再做自动抓取。
- 主要摩擦是忘记 review：先补一条主动提醒渠道。
- 主要摩擦是未来安排不直观：再做 Calendar。
- 保存顺手但资料从不被引用：调整找回和使用入口，不能只增加摘要数量。
- 核心循环已能稳定使用：再考虑 wiki 自动维护和 e-ink 输出。
