# 01 · 流程与交互

依赖：[范围与默认值](00-scope.md)、[数据与状态](02-domain-and-state.md)。本文件描述行为，不锁定视觉设计。

## 导航和界面边界

| 入口 | 内容 |
| --- | --- |
| 今日 / 日期页 | 自然语言录入、可编辑 daily note、review、需要留意的事项。 |
| Pages | 搜索和打开资料/主题页，新建普通页。 |
| 未来事项 | 按日期查看任务和事件，检查准备时间与截止日期。 |
| 查找 / 暂放 | 按标题或正文搜索；暂放内容是可选筛选，不展示必须清零的徽标。 |

Review、引用选择与事项详情可以在页面内展开或侧栏呈现，不要求增加独立路由。

日期切换后页面明确显示当前日期，并提供“回到今天”。跨午夜不强制跳转正在编辑的页面，提示“已是新的一天，可切换到今天”。

## F00 · 进入个人工作区

采用 Supabase 数据服务后，建议首版提供最小登录入口：已有会话直接进入今日页，无会话先登录；不增加协作、公开注册引导或邀请流程。具体登录方式在配置 Supabase 项目时确定。

会话失效时保留当前待保存文字并提示重新登录，不把登录失败显示成保存成功，也不要求用户重做已成功提交的 AI 操作。

## F01 · 首次进入今日页

1. 取得工作区本地日期；创建或打开该日期唯一的 Daily Page。
2. 若页面已有用户内容，直接打开，不重新生成覆盖。
3. 若是空白页，先显示可编辑基础页和明确的任务/事件事实，再发起 AI 草稿生成。
4. AI 可以组织标题与少量行动建议，但所有已知日期安排来自保存的记录。
5. 用户生成期间开始编辑时，返回结果转为“待加入的草稿”，不覆盖正文。
6. 模型失败仍可写笔记和操作事项；显示失败与重试入口。

默认起始结构可以包含今日安排、建议行动、随手记、回顾。标题和区块均可改名、移动或删除；没有被强制保留的正文模板。

“需要留意”是页面外的轻量日期状态区，用于新到事项、截止变化和待合入内容；不属于不可编辑的正文。不重复铺满整页，详细内容可展开。

## F02 · 自然语言录入

例：在 2026-10-13 输入“周五之前交材料，周三开始准备，参考这个链接：https://example.com”。

1. 点击提交后，先保存原话、输入时区、时间与当前日期页位置。
2. 在该位置显示“已保存，整理中”；用户可以继续录入或编辑其他内容。
3. AI 返回：任务“交材料”、截止 2026-10-16、关注/准备日 2026-10-14，以及链接资料。
4. App 校验后一次写入，页面相应位置呈现任务及资料引用，不再重复铺开同一原话。
5. 回执显示“已记录任务；10/14 开始准备，10/16 截止；已保存链接，尚未提供正文”。可展开原话、纠正或撤销本次整理。

一句输入可以产生多个相关对象，不强制选 TODO/Events/Notes。普通笔记保留用户表述，AI 摘要单独标注。

“过阵子看看”保留为笔记/建议，不编日期；明确说“要做 X，但还没安排时间”可以创建无日期任务。链接本身不等于阅读待办。

提交去重和失败恢复见 [AI 契约](03-ai-contract.md)。录入尚未成功保存时显示“未保存”，不得显示整理成功。

## F03 · 自由编辑

- 支持段落、标题、单层列表、待办、引用文字、事件呈现和页面/Block 引用。
- 支持新增、编辑、删除、移动 Block；排序可以用简单移动操作，不要求复杂拖拽编辑器。
- 明确显示保存中、已保存和保存失败；失败时保留待保存内容。
- 编辑普通文字只影响该段落。选中文字后可主动“整理这段”，结果按差异确认应用。
- 编辑任务行标题/日期或勾选状态，更新同一任务并给出可撤销反馈。
- 如果任务行标题中写入疑似日期，不自动改变日期字段；通过自然语言操作或明确日期控件修改，避免两套含义混用。
- 编辑正在被 AI 处理的原始录入时，使旧结果失效；保留新内容，允许重新整理。

页面“完全可编辑”指内容、结构和事项都能通过明确操作修改，不承诺删除普通句子就自动取消某项承诺。

## F04 · 手动保存资料与引用

1. 在 Pages 新建页，写标题、来源链接，粘贴正文、摘录或个人备注。
2. 自动保存，正文划分为基础 Blocks。来源摘录与个人结论可通过引用块/普通文字和标签区分，不要求复杂表单。
3. 返回 daily note，打开引用选择器，输入标题/关键词。
4. 可选择整页；也可进入页面，选择具体 Block。插入引用卡/引用行，显示标题、简短预览及定位入口。
5. 点击引用进入原页并定位 Block；原页可以查看“被哪些页面引用”。

选择器可采用 @ 触发或工具栏按钮，具体视觉实现未定；两者不是必须同时实现。

引用原文默认展示最新内容。需要保留当时原句时，用普通引用文字块复制摘录并附来源链接，该摘录是独立文本，不伪装成动态引用。

资料内容修改后动态引用显示新内容；移除引用不删除资料。目标被移到回收站时显示“原内容已移除”，保留定位信息，不显示空白或错误内容。

## F05 · 未来事项回流

例：“20 号提交材料，17 号开始准备”。

- 录入日保留记录和任务关联。
- 17 号起进入“需要留意”，说明“你安排从今天开始准备”。
- 用户若指定 18 号处理，18 号的每日页可纳入对应任务引用。
- 20 号进入截止提示；未完成则保留已过截止状态。
- 完成/取消后停止生成未来行动提示，历史记录仍可查。

没有准备日期时不自行补一个。带“明天”“下周”的输入按录入时的日期和时区解析；回执展示具体日期。

未来页提前存在时，新的相关事项先出现在更新提示中，可一键加入正文；日期状态区始终基于最新事实，不能因为正文未合入而遗漏截止。

## F06 · 暂放、移除和取消

| 操作 | 结果 | 当下交互 |
| --- | --- | --- |
| 今日任务行“暂放”/移除 | 移出该日正文安排，停止自动顺延；保留任务与截止 | “已暂放，今天不再推荐 · 撤销”；无去向弹窗。 |
| 今日有截止任务暂放 | 正文移除，截止提示保留 | 回执补充“截止提示仍保留”。 |
| 删除资料引用 | 只移除该引用 | 可撤销；原资料不变。 |
| 修改历史页里的任务引用/删除引用 | 只改变历史页面的呈现 | 不顺带暂放今天的任务。 |
| 明确取消任务 | 任务状态变为 cancelled | 历史保留，未来提示停止，可恢复。 |
| 自然语言“周五再做” | 改计划日，清除针对该次安排的暂放状态 | 回执显示旧日期→新日期。 |

撤销不能覆盖之后的其他编辑；有冲突时保留当前状态，说明无法直接撤销，并展示可恢复的原值。

## F07 · 未完成与次日草稿

昨日未完成不等于全部移入今天。

- 今天明确安排的事项与日期事实优先进入初稿。
- 最近一份每日页里未完成、未暂放且没有未来计划日的任务，可以成为接续候选；默认最多 3 条。
- 候选标为“建议接续”，展示不改变原任务计划日；点“今天做”、主动改日期或开始处理时再更新今日安排。
- 其余候选在可展开的 review 区域保留，避免强制逐条处理。
- AI 新提出的行动是文字建议，转为待办才获得独立任务状态。

明确暂放后不因“仍未完成”再次自动成为次日候选。用户主动找回或重新指定日期后可恢复；截止提示独立有效。

## F08 · Review

1. 打开当日 review，看到已完成、未完成的摘要及明显期限。
2. 可自由填写“今天有什么变化”“明天想怎样调整”；问题可跳过，不要求逐条选择。
3. 明确操作如“材料等回复，试用项目放到周五”按录入规则处理；不确定对象只询问必要的一项。
4. 保存 review 原话，再生成明日草稿。已有明日内容时呈现可合入更新，不覆盖。
5. 重试或重复提交不会复制事项或追加同一份草稿。

跳过 review 后：原内容和任务状态仍在；再次进入今日页可从最近一份计划恢复，过期事件留在历史，不自动变为待办。

## F09 · 历史、当前状态与未来列表

普通日记文字保持用户保存的版本；任务和动态引用显示当前内容/状态，历史页标注这一点。可从事项详情查看完成、改期、暂放等变化，避免把最新状态误读成当时就完成。

未来列表区分“计划处理”“准备关注”“截止”“事件”，同一任务可有不同日期标记，但保持同一任务身份。过期事项显示逾期，不自动完成；事件过去后作为历史保留，需要跟进时再明确建立任务。

## 通用状态

| 状态 | 应有体验 |
| --- | --- |
| 无内容 | 能直接写，不要求先配置项目/分类。 |
| AI 处理中 | 原始输入已保存，其他操作可用。 |
| 解析有疑问 | 保留已知信息和原话，给一条具体澄清，不重复建事项。 |
| 请求失败 | 清楚区分保存失败与 AI 失败，能重试。 |
| 保存冲突 | 保留本地编辑和已存版本，不采用静默最后写入覆盖。 |
| 找不到引用 | 保留引用位置，显示目标已移除或不可用。 |
| 无新推荐 | 可以为空，不为填满页面编造内容。 |
