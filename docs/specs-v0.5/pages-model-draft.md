## 2. 三类 Page 与写权限

**[建议]** 一个 Page 身份表、一个正文真源，用 `kind=day|user|ai` 区分权限，避免三套编辑/引用系统。URL 是 user 页属性，不是第四种 kind；保留稳定 page_id、workspace_id、revision、软删除及已有树关系。AI 页的展示名不能成为数据库枚举。

| 类别 | 来源与身份 | 谁能写正文/标题/语义属性 | 关系与恢复 |
| --- | --- | --- | --- |
| day | [确认] 用户当日记录；[建议] 工作区+日期唯一，垃圾箱仍占身份 | 用户；AI 只可在首次初始化的受控窗口写 | 沿用固定 Days 及已有日页恢复规则；AI 重跑不能重新初始化 |
| user | [确认] 用户创建、链接保存、AI 页复制 | 用户；初始化阶段按所选 O1/复制操作填入，之后 AI 永不回写 | 沿用 v0.4 嵌套/移动/删树/恢复；复制有新 ID、独立版本 |
| ai | [确认] 从用户记录派生；[建议] 持久页面 ID + 可替换生成版本 | 索引服务仅写 ai kind；用户通过复制或源记录纠正，不直接编辑原 AI 页 | [建议] 与用户树分开管理；AI 内部组织方式尚未决定，不把其父关系塞入用户树 |

**[建议]** 权限由应用/存储命令检查，不由提示词保证。普通用户编辑命令拒绝 ai 正文写入；索引发布命令拒绝 day/user 写入、Task/Event/Placement 操作和用户树移动。初始化命令只对新 ID、未初始化且版本匹配的页面生效，提交正文与 `initialized_at` 一次完成；即使用户清空正文、恢复垃圾箱或索引重跑，也不能再次获得初始化权限。用户先开始编辑则关闭该窗口。

页面正文中的外部原文、用户备注、初始化生成文字需保留来源类别。用户页的控制权属于用户，并不使网页引文自动成为其个人指令或事实主张。

### AI 页复制到用户页 [建议]

在用户明确 Copy 操作时，从指定 AI 页面版本创建 user 页，记录 `copied_from_page_id/revision` 和复制时间；初始内容是快照，之后只归用户写。原 AI 页更新不改副本；用户副本编辑不直接覆盖原页，而作为下一轮带来源的新输入。复制不继承 URL 去重键，否则会与 v0.4 单 URL 单页不变量冲突；保留普通来源引用即可。重复传输同一复制操作不重复建页，明确再次复制是新操作。目标目录必须同工作区且可写。

## 3. 最小逻辑对象 [建议，非 SQL 定稿]

| 对象 | 所需信息与边界 |
| --- | --- |
| Page | id/workspace/kind/title/body_revision/initialized_at/deleted；day_date 仅 day，source_url/url_key 仅相应 user 页；树字段沿用 v0.4 |
| ExplicitReference / Save | 沿用真实卡片引用与保存历史，不能被推断关联替代；Linked from 只读真实引用 |
| IndexEvent / IndexJob | event_id、plan/review、源日/目标日、输入快照摘要、规则版本、状态、attempt、错误与费用关联 |
| SourceManifest | page_id+revision+kind+来源类别、必要 Task/Event/Placement 版本、删除/缺失标记；记录实际读了什么 |
| GeneratedRevision | AI page_id、job_id、正文/主题键、证据源及版本、生成器版本；发布前不成为当前版本 |
| InferredRelation / Claim | 仅派生：端点、来源版本、推断内容/冲突状态、所属生成版本；不改真实卡片或承诺 |
| PublishedIndex | 工作区的当前已提交知识版本，含页面/关系映射和 source watermark；可整体切换，避免半新半旧 |

一个 AI 页可能关联多个主题/证据，不能把标题直接当唯一身份。首版建议服务端保守分配稳定主题键、同键复用；不确定是同主题时保留独立候选，不自动合并用户页面。具体主题消歧算法待实验，不能承诺“相同食谱”永远自动识别。

## 4. plan/review 事件与可重跑索引 [建议]

1. **先保存用户动作。** plan/review 的已提交事件带稳定 event_id。未保存的输入不进入后台索引；review_saved 与 index_ready/日草稿状态独立，索引失败不阻止记录和 review 完成。明确 plan 对应哪个现有按钮/提交点待 01 修订，开页不隐式等于 plan。
2. **固定输入。** 每个作业记录当时可访问源版本、源日和目标日、规则/模型版本、范围与规模。增量选择基于上次成功 watermark 和变动页面，包括删除。首次/全量重建用同一协议，不能只读今天而声称知识库已完整纠正。
3. **幂等与重试。** 同 event_id+输入摘要+规则版本复用同一个逻辑 job。丢回执先查结果；外部调用费用未知时不盲重发。人工主动“重新索引”是新请求，可复用输入，但需独立 attempt/预算；输入变化或规则升级产生新 job。
4. **生成暂存。** 模型只产 AI 页/证据/关系候选，不能执行源文里的命令。先检查同工作区端点、来源版本、权限、schema、预算和输入范围；失去访问权的源不得保留可读内容。
5. **条件发布。** 发布检查预期知识版本及所有依赖源的当前版本。任何依赖变化，包括新增纠正、源删除/编辑，结果作废或重排，不让旧作业晚到覆盖新纠正。用工作区源变动序号捕捉未在旧 manifest 中的新纠正。多页结果及关系在同一发布边界切换，失败保留前一知识版本。
6. **变更后失效。** 源编辑/删除后，依赖结果标 stale 并停止作为最新事实使用，下次 plan/review 重算；删除时立即隐藏依赖的可见内容，不能等下轮再撤去已删源。重建只替换 AI 层，不动用户记录。AI 页撤回保留稳定占位与复制来源，不能顺带删除用户副本。
7. **派生日建议。** 推理以当前源+可用知识版本输出独立建议。是否在初始化直写或用户选择后应用见 O4；无论哪条，不能由索引作业自动完成、取消、改期已有事项，或恢复暂停接续。

索引不是“回放用户操作”：重读“明天买盐”不能每次创建一个新任务。新承诺/事项归属需要沿用受控命令、稳定来源身份与既有确认协议；AI 页出现 TODO 字样没有 Task 写权限。

**容量和费用：** 沿用 03 的共享日预算、预留/结算、超时对账。增加索引不能获得第二份预算。v0.3 E1 显式关联全文规则在修订前保留；不能用 AI 页摘要偷偷替换它。本稿提出另一个知识索引作业及隐式关系候选层，不宣称已解决全库容量。源超窗时作业失败/延期并保留旧知识，不能默默删源后标完整；分批索引需单独定义覆盖范围和一致性协议后验证。

## 5. 用户内容如何覆盖推断 [确认目标；以下机制为建议]

- 人工原始记录和用户明确纠正是证据层；AI 页与隐式关联是可重建派生层。AI 的旧摘要或多次重复推断不能凭数量压过一条明确用户纠正。禁止把 AI 自己上轮输出当新增独立证据形成自我强化。
- 将“事实内容”与“用户意图”分开：保存网页中“加盐两勺”不等于用户要求改自己的配方。用户写“上一版食谱太淡，我这次加盐”才是具有人物、时间、范围的纠正证据；不修改原记录。
- 纠正匹配必须保留目标/时间/语境。用户前后记录冲突而无法辨明时，生成层保留分歧/不确定并引用两处来源；不猜哪条作废，不改任务承诺。新日期也不自动使外部引文胜过用户的明确说明。
- 索引每次读取变动的用户页和 threads，定位受影响 claims，撤回或修订旧推断并保留证据。匹配不确定是待验证能力：不得承诺自然语言纠正必定识别。未解释清楚前，不用于确定性任务动作。
- 用户把 AI 页复制出来后未改的那部分仍保留 AI 来源；用户实际改写/补充作为人工证据。最小可行来源粒度与编辑器保存模型需要后续实验，若只能页面级追踪，就标明混合来源，不能伪称逐句可靠。

## 8. 未来搜索与对话接口 [建议，仅留边界]

- `getPage(id, revision?)`：返回种类、可见内容、来源、版本/过时标记；同工作区校验先于读取。
- `listKnowledge(version, cursor)` / `getEvidence(aiPageId, revision)`：浏览与引用可重建知识和证据；缺失/删除用占位，不泄露旧正文。
- `retrieveContext(query, scope, asOf?)`：未来可接全文、向量或目录索引，返回真实源、AI 页、证据和知识版本；检索器是可替换实现，不在本轮选数据库/embedding。
- `composeDayContext(date, purpose, indexVersion)`：明确区分用户源、确定性 Task/Event 事实、显式引用与隐式候选，返回 manifest 与完整性状态。推理结果只读，应用仍走受控命令。
- 对话可以读这些接口，不能因拿到 AI 页而获得写用户内容/事项权限。搜索与对话的 UI、计费和执行协议不在本轮实现。
